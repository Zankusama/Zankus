# 脱敏规则表

> 配合 SKILL.md §5 使用。收录三级替换判定、PII 规则与落盘后扫描实现（对应 §5.1 替换标记形态 + §5.5 不许做的三件事）。

## 5.2 替换什么（按判定强度分三级）

| 级别 | 触发条件 | 例子 |
| --- | --- | --- |
| **A 高置信形态** | 形态本身就够——命中即替换 | 私钥块（**含只有 BEGIN 的半截块**）、JWT 三段式、`AKIA…`、`sk-…`、`ghp_…`、`xox…`、`Bearer <长串>` |
| **B 强凭据键** | 键名含 `password / passwd / pwd / passphrase / passcode / secret / credential / salt / apikey / api / accesskey / privatekey / clientsecret / signingkey / encryptionkey`，**值再短也替换**（长度下限 1） | `PASSWORD=abc` **替换** |
| **C 弱凭据键** | 键名含 `token / key / auth / bearer / session / sid / cookie / sign / signature / nonce / cert / jwt / oauth / refresh / access / csrf / state_id`，**只有值高熵时才替换**（长度 ≥20 且同时含大小写与数字，或 JWT 形态） | `SESSION_TOKEN=aB3xK9…` **替换**；`TICKET_TOKEN=PR-1024` **不替换** |

**⛔ 键名命中「只作加权，不单独构成替换理由」**——这是 B/C 分级的由来，也是“不动业务数字”的护栏。

**业务数据尾标优先（把日期从“secret 键”里救出来）**：
键名最后一段命中 `date / time / at / id / no / num / count / version / url / path / name /
type / status / mode / ref / index / owner / desc / limit / timeout / policy / env …`
→ **该键一律不动**。这就是 `SECRET_ROTATION_DATE=2026-09-23` 必须原样保留的原因。

## 5.3 PII（邮箱 / 手机号 / 身份证）：**默认关闭**，只在强上下文命中

- **为什么默认关**：这三类正则**极易误伤业务标识**。实测反例——`requests@2.31.0`（包名@版本）
  被当邮箱、`100000202401011234`（机构码+日期+序号）被当身份证、`13912345678`（快递单号）
  被当手机号。**本 skill 的第一优先级是“关键信息不漏”，所以默认不动。**
- **强上下文定义**（满足任一才命中）：显式键（`phone=` / `email=` / `身份证=`）；`+86` / `86` 前缀；
  值里带分隔符（`138-1234-5678`）；邮箱域名的 TLD 是**纯字母**（这就排除了 `pkg@1.2.3`）；
  18 位身份证号**校验位正确**。
- 团队内确实需要时用 `--pii` 打开；其余场景建议把这类值当**业务标识逐字保留**（SKILL.md §3.2 契约）。

## 5.4 脱敏的唯一推荐实现点：**落盘后扫描**

“模型直写文件”和“脚本落盘”两条路径必须在脱敏上**收敛到同一行为**，
所以机制定在**落盘之后**：`--scan` 体检 → `--redact-file` 就地替换。
这样既不会出现“A 路径默认脱敏、B 路径完全没有脱敏”，也不需要把文档塞进 stdin。
