# resume 接手流程

> 新会话收到 `resume`（或用户给出交接文档路径）时按本文件执行。含两部分：① resume 侧解析顺序；② 接手方行为契约全文。

## 一、resume 侧解析顺序（新会话收到 `resume` 时按此执行）

1. 用户给了路径 → 用它，跳到第 4 步。
2. 否则读 `./handoff/LATEST`（一行文本，内容是文件名）→ 取其指向。
3. 无 `LATEST` 或指针失效 → 取 `./handoff/` 下 `HANDOFF-*.md` 中**修改时间最新**的一份。
4. **打印你选中的绝对路径，请用户确认，确认后再开工。**
   ⛔ **不要静默开读**——选错文档比不选更贵。
5. 目录不存在、或没有 `HANDOFF-*.md` → **明说"没找到可接的交接文档"**，并问用户是不是新起的会话。

> 命令行对位：`python3 scripts/handoff.py --latest` 会打印第 2/3 步选出的绝对路径与来源（`LATEST 指针` 或 `目录内 mtime 最新`）。
> 落盘时**同步维护 `LATEST`**（SKILL.md §4 步骤 6）——否则 `resume` 只能按 mtime 猜。

### 一·补：陈旧度检查（2026-10-11 v2.2.0 新增，第 4 步确认时一并执行）

交接文档会腐烂（行号偏移、路径消失、state 后续有新记录）。认领时在**报路径请确认的同一轮**顺手算一次陈旧度，三档标注随路径一起报给用户（⛔ 只报标注，**不改文档本体**）：

| 档 | 判据（命中即该档，从重到轻判） | 接手确认里说 |
| --- | --- | --- |
| 🔴 严重陈旧 | 落盘 > 7 天，**或**文档 `ARTIFACTS` 里的关键路径已不存在 | "该文档已严重陈旧，CURRENT_STATE 与路径需逐条验证后再动" |
| 🟡 陈旧 | 落盘 1–7 天，或 `state.json` 的 `updated_at` 晚于文档落盘，或 workspace 有 git 且文档落盘后有新提交 | "已隔 N 天/有新变动，先核对 CURRENT_STATE 再开工" |
| 🟢 新鲜 | 落盘 < 24h 且无上述信号 | 只报路径 |

- 判据阈值（24h / 7 天）是**个人启发式**（自标，无实证背书）。检查动作全部本地只读：文档 mtime、`state.json` 的 `updated_at`、`git log --oneline -1`、`ls` ARTIFACTS 路径；任何一步跑不了就跳过该项，不阻塞接手。
- 若 META 含**交接链深度** ≥ 2：无论哪一档，追加一句"本文档已是第 N 手转述，关键数字建议回溯原始产物核验"（多轮转述的复合损失见 Compaction Cliff，arXiv:2608.22752）。

## 二、接手方行为契约（逐字可用块）

产出方有自检 prompt 块（SKILL.md §1.3），**接手方同样需要一份**——因为“写在文档里的 `⚠️` 标记不改变行为”。

```markdown
<TAKEOVER_CONTRACT>
你现在接手一份别人写的交接文档。按顺序做四件事：

1. 先读两处，再动任何手：
   · 文档第一行的「未答问题」（可能有 ≤5 条）
   · UNVERIFIED 段（那里是“上一位只是以为”的断言）
2. **开工前把 CONSTRAINTS 整段逐字重读一遍**（不是凭初读印象）——约束的存活靠
   搬运原文、不靠摘要器理解：压缩后把约束原文重新附上，合规可从 31.8% 拉到
   99.7%（Lost in Compaction，arXiv:2608.11242 表9，2026-10-11 回源）。
   重读完仍当**硬约束**逐条遵守——即使你觉得不合理，也先照做，除非用户当场改口。
3. 凡影响你**第一步动作**的 [仅推断] 项，**先验证再开工**。不要把它当事实用。
4. 发现文档与现状冲突（文件没了、行号偏了、结论被证伪）时：**停下来问人**，
   ⛔ 不要静默改文档、也不要静默按文档硬做。

三条禁令：
· ⛔ 不要把 UNVERIFIED 里的猜测当结论往下推。
· ⛔ 不要因为“文档里没写”就认为“这件事没发生过”——先看 DISCARDED。
· ⛔ 不要在未确认的情况下重走 DISCARDED 里的路。
</TAKEOVER_CONTRACT>
```
