# 工作交接（baton）v2.3

把「正在飞的工作」压成一份**下一棒能冷读接手**的交接文档。

主张只有一句：**买的是可移植与不失真，不是压缩率。**

参考实现（Matt Pocock 的 `handoff`）买的是可移植性；本 skill 在其上净增三件事——**漂移自检**、**逐字保留契约**、**三档静默自适应**。

**引用基准澄清（2026-10-11，防"挂名被原教旨对照"）**：Matt 原始实现是**极简派**（16 行单文件、无字段模板、写 OS 临时目录——"Save to the temporary directory of the user's OS…not the current workspace"、仅 User-invoked 手动触发；2026-10-11 对原文件一手核verified）——他贡献的是**哲学**：portability、"把'以为'写成'事实'"的警告、"有路径只写路径"。本 skill 的 15 字段重型 schema 的直接谱系是**社区衍生重型模板**的演化（如 qdhenry 的 comprehensive handoff 命令等；2026-10-11 核验），`./handoff/` 持久落盘是对 Matt 临时目录的**有意分歧**（官方 memory / multisession 模式支持持久化）。Matt 名义只限哲学与方向；schema 与机制不归他。

> **使用者只需要记两个词：`交接` 与 `resume`。**（见 §1.5）

---

## 0. 硬边界（先声明，防过度承诺）

- 本 skill **不能执行压缩**。没有任何脚本或指令能调用 harness 的 `/compact`。它只**产出交接文档**并**指路**。
- 本 skill **不测量 token**。宿主通常不暴露 token 指标；**绝不猜测一个 token 数并当作已测量上报**。
  （⚠️ 边界澄清：§1.3 的“客观体量代理”记的是 agent **自己数出来的工具调用次数 / 读取文件数 / 输出量级**——数自己做过的事**不是**猜 token。）
- 本 skill **不依赖任何客户端专属 hook**。触发完全靠「节拍 + prompt 自检 + 用户显式触发」。有 hook 的环境可以更准，没有也不失效。（可选主动提醒 hook 见 §7）
- 监控是**建议性**的，不能强制中断你的执行。
- **不绑客户端机制**：交接的“下一棒用途”是**自然语言输入**，不是某个客户端专属的参数键（见 §4 步骤 0）。

## 1. 触发：三档自适应

> **设计依据（为何由外部机制决定打包）**：长会话越久上下文质量越低（context rot），而压缩摘要恰恰发生在会话末尾——等于让状态最差的模型执行最关键的有损步骤（Claude Code 团队成员流传的表述 *"the model is at its least intelligent point when compacting"*；⚠️ 社区流传表述、未在官方文档回源，仅作方向参考，2026-10-11 核查）。所以 baton 把"何时打包"放在**外部节拍 + 客观信号 + 用户显式**上，不靠模型自感。

### 1.1 三档定义（⛔ 全文唯一一张档位表）

| 档位 | 进入条件 | **唯一**产出 | 是否出声 |
| --- | --- | --- | --- |
| **L0 静默** | **默认档**。命中项 = **0** | 无文档。仅向 `./handoff/state.json` **静默追加**一条自检记录 | ⛔ 完全不出声 |
| **L1 轻检** | 命中项 = **1** | 回复末尾**追加 1 行**（§1.6 的定稿文案），**不落盘** | ✅ 仅 1 行，同一会话最多出现一次 |
| **L2 深检** | 命中项 **≥ 2**，**或**命中下列任一硬触发 | **交接文档**（§3）+ `LATEST` 指针 + 打印**绝对路径** | ✅ 落盘 + 打印路径 |

> ### 「命中项」的定义（本节唯一，全文不再另算）
> **命中项 = 症状类别数，取值 0–5。**
> ⛔ **不是 15 个勾选框。** 同一类别里勾中 3 条，仍然只算 **1 项**。
> 症状编号全文统一用 **1–5**（见 §1.3 自检清单），不再出现“症状 1/4”“症状 1/2”这类混用写法。

**硬触发（命中任一 → 直接 L2，不看命中项数）：**

1. 用户显式要求交接 / resume / handoff / “该交接了”
2. **类别 1（指令退化）或类别 2（污染固化）**里命中任一条
3. §1.3 的客观体量代理异常（连续 3 个工作单元无任何落盘产物，或单轮工具输出量级异常）
4. 你判断“再过几轮就写不清楚了”

**L2 是主动义务，不问不请示（2026-10-11 定稿）**：硬触发或命中 ≥2 类一旦成立，**直接打包**（同一次 pass 末尾落盘，§4）——**不等用户说「交接」，也不输出"是否打包"的询问**。决定权的分界就在这里：**L1 把"是否打包"交给用户定，L2 的决定已经做出**。可选提醒 hook 对应同款双分支（§7.1）：L2 级信号 → 催办行（指示直接打包），sub-L2 软信号 → 询问行（用户定）。

**verdict 命名（只影响记账时写哪个词，不改变上面的档位判定）：**

| 命中情况 | verdict | 落在哪档 |
| --- | --- | --- |
| 命中 0 类 | `HEALTHY` | L0 |
| 命中 1 类，且不含类别 1/2 | `WATCH` | L1 |
| 命中 2–5 类 | `DEGRADED` | L2 |
| 含类别 1 或 2（任意一条） | `CRITICAL` | L2 |

**L0 是默认，不是降级。** 没有异常就当没发生过这件事——不要打招呼、不要汇报“我已检查过上下文”、不要输出体检表格。仪式化输出本身就是噪音。
⚠️ 但 L0 **仍然要静默记账**（§1.2 可回查）——**写文件不算出声，不破静默**。

**懒惰压缩原则**（实证支撑，2026-10-11 补）：一次压得深、压得好，优于频繁浅压——Claude Code `/compact` 实测一轮压缩后安全规则留存 **53%**、五轮后仅 **10%**（"Compaction Cliff"，arXiv:2608.22752；20 个生产 agent 配置、Sonnet 4.6，2026-10-11 摘要回源）。**不要**因为"勤检查更安全"就频繁产出交接文档——每多一次有损步骤就多一份复合损失。

### 1.2 节拍（cadence）：什么时候做 L0 那一眼

不做独立往返。**L0 的“扫一眼”折叠在你本来就有的思考里**，设计意图是**不新增模型往返**。

> ⚠️ 措辞纪律：**不要**声称这个自检“成本约等于零”——那是一个未经测量的量级断言，
> 与 §0 的诚实纪律冲突。可核对的表述只有一句：**它折叠进既有思考，不新增模型往返。**

采样点：

- **每个工作单元结束时**（一个文件改完、一个测试跑通、一个子任务收口）
- **每 10 轮**（兜底节拍，⛔ 不是硬阈值）
- **准备打开一批大文件 / 做一次大范围读取之前**
- **每次交接前后**
- **用户显式要求时**（见 §1.5）

> ⚠️ 节拍是**采样策略**，不是信号。它对“突然变长”不敏感（例如用户一次粘贴五万字）——所以下面还有**突变信号**，两者叠加使用。

**每次采样都静默记账**（L0 也要）：
```
python3 scripts/handoff.py --log --turn <N> --hits <0-5> --verdict <V> \
    --tool-calls <N> --files-read <N> --output-scale <small|medium|large> --artifacts <N>
```
记进 `./handoff/state.json`，只留最近 20 条。
**这就是“该触发却没触发”唯一的事后凭据**——没有它，用户事后无从判断是“系统没盯”还是“盯了判错”。
（脚本不可用时：自己把这一行追加进 `state.json`。⛔ 脚本是便利设施，不是前置依赖。）

**其他常用参数**（完整列表跑 `python3 scripts/handoff.py --help`）：

- `--selftest`：自测脚本环境（脱敏正则是否误伤业务数字、保留样本是否全过）。**交付前必跑一次。**
- `--fields`：打印 15 字段顺序（与 §3.1 表格对齐）。
- `--state-show`：查看最近 20 条自检记录。
- `--latest`：打印 resume 该认领的交接文档绝对路径与来源（LATEST 指针或目录内最新）。
- `--dir <path>`：覆盖默认 `./handoff` 目录。
- `HANDOFF_DISABLE=1`：环境变量，整体静默关闭（不写 state.json；--help / --selftest 仍放行）。

### 1.3 突变软信号与漂移自检（不靠节拍，察觉到就该升级）

**四个早期客观征兆**（成本最低，出现即对照下方清单判类）：

1. **重读**：再次读已读文件、再次 grep 同一模式（漂移的早期客观征兆）。
2. **同错反复**：同一报错再次出现，或第二次做同一个失败修复。
3. **用户连续纠正**：“不对”“不是这样”“我说过了”。
4. **文本体量突变**：本轮新增远大于前几轮，或解释越写越长。

⚠️ **关于征兆 3 必须一起读的免责**：观测到压缩后 5 步内纠错率 **41.9% vs 基线 17.7%**（2.37×），升高**至少持续 30 步、120 步时尚未完全消退**；但**原作者明确拒绝因果解读**——作者原话（两句均 2026-10-11 逐字回源）："sometimes I compact because things are already going badly, which by itself would inflate the post-compaction spike"（运维者可能因为会话已经变糟才去压缩，这本身就会抬高压缩后的尖峰），并说明 "The correction measurement is observational, not an experiment"。→ **这是观测性研究、原作者不声称因果**（等级 C，单一实践者、162 天、873 次压缩；来源：langwatch.ai/blog/context-tax-when-to-compact，2026-08-02）。**它只能当"值得看一眼"的提示，不能当作"压缩会害人"的结论。**

⛔ **不要引入「压缩次数 ≥ N 次就交接」这类阈值**：该维度**没有任何来源给出数值阈值**——现有理论工作（arXiv:2607.08032，preprint 立场而非领域共识，2026-10-11 摘要回源）只形式化单次压缩，并指出重复压缩"almost never measured"（几乎从未被测量）；若你自用某个次数，必须**明确标注为个人启发式**，不得伪装成实证。

**客观体量代理（本清单里唯一“不是自观测”的一条）**：上面征兆 1–4 全是**自观测**信号，而**退化恰恰损害自观测能力**——判官不可靠时，正是最需要它的时刻最容易静默。所以必须叠加一条**客观、零依赖、agent 自己就能记**的代理。每个工作单元结束时顺手数自己做过的事：本轮**工具调用次数** / 本轮**读取文件数** / 本轮**累计工具输出量级**（small / medium / large，只报量级、不报数字）/ 本轮**新增落盘产物数**。

> ⚠️ 边界：**数自己做过的事 ≠ 猜 token。** 本 skill 仍然绝不测量 token（§0）；工具调用次数是 agent 轨迹里客观可数的事实。

**升级条件（满足任一 → 直接 L2）**：

- **连续 3 个工作单元无任何落盘产物**（工具在转、什么都没落地——这是“空转”的客观形状）。
- **单轮工具输出量级异常**（一个工作单元内冲到 `large`，且同时命中征兆 1 或 2）。
- 单轮工具调用次数 / 读取文件数明显高于本会话此前的水平。

⚠️ 这几个阈值（含”3”）是**个人启发式**，不是实证阈值——引用时必须自标。脚本只**报数**、不判定（`--log` 会算 `no_artifact_streak` 给你看）。**总自标（2026-10-11）**：本 skill 的触发信号（漂移自检/空转计数/体量代理阈值）全部为**自创启发式**，无官方或实证阈值背书——官方机制对”何时压缩”只用 token 阈值，本节这些信号在官方体系**无对应物**。

**临界区（逼近 L2 但未达硬触发）→ 显式建议，不落盘**：客观数据逼近升级条件但未命中时，在回复末尾追加**一次** §1.6 定稿文案（**带原因**），把"是否打包"交给用户定。⛔ 此档**不产文档**——产文档是 L2 的事（§1.1）。

**临界区判据（v2.3.0 触发源回正；两类软信号，⛔ 都只出询问行、绝不出催办行）：**

1. **空转轴 streak**：连续 **2** 个工作单元无落盘产物（阈值 3 的前一步）。**取值来源回正**：`state.json` 自报（`no_artifact_streak`）优先；**没有自报账的普通会话改用客观值**——`baton_tick.py` 由会话事件时间线切工作单元算出，输出 JSON 用 `streak_source` 标注 `"self_report"` / `"objective"`。⛔ v2.1.x 曾把触发源绑死在自报账上：不调 `handoff.py --log` 的会话根本没有自报账，自动提醒对主场景完全失效（v2.3.0 修复）。
2. **体量轴（v2.3.0 新增）**：用户轮数 ≥ **15** 或会话跨度 ≥ **60 分钟** → 只进询问行，⛔ 永不置 `l2_objective_hit`（拍板：体量轴仅出询问行不出催办行）。

⛔ **空转轴**判据只有 streak 一条——"单轮 `large`+重读"是升级条件（→ §1.1 硬触发第 3 条，直接 L2），不在这里重复：tick 的 `read_dup` 是全会话累计量、客观上测不了"单轮"，hook 不承担此判定（该判定归 AI 自检——AI 数自己的单轮可以测准）。`baton_tick.py` 把这类软信号放在输出 JSON 的 `packaging_advisory.reasons`（白话原因）供你和 hook 消费；streak 达到 **3** 硬触发时它同时置 `l2_objective_hit=true`（→ 直接走 L2，不再询问）。

⚠️ 本节数值（2 / 3 / 15 / 60）全部**自标为工程启发式**（依据：证据调研报告 2026-10-12——学术查无任何轮数/时长阈值；空转 2-3 与 JetBrains/CoderClaw 的"连续 2-3 次无状态变化"惯例量级一致；轮数/跨度无任何先例，仅作 token 占比不可见时的代理）。⛔ 引用时不得声称"有学术/权威依据"。

> **客观体量代理的脚本实现（多客户端适配）**
>
> 客观计数由 `scripts/baton_tick.py` 实现，支持 9 个 provider：
> workbuddy / doubaowork / qoder / qoder_cn / qwenwork_cn / zcode / autoclaw_official / copilot / autoclaw_legacy。
>
> 用法：`python3 scripts/baton_tick.py <workspace_dir>`
> 脚本按 workbuddy → doubaowork → qoder家族 → zcode/autoclaw/copilot → autoclaw_legacy 顺序自动探测路由。
>
> 输出 JSON 里 `provider` 字段标注本次实际命中了哪个客户端；
> 若 `objective_available=false`，会显式给出 `objective_unavailable_reason`（fail-open，不静默失效）。
>
> Trae 家族（trae-cn）核心 DB 加密、CodeBuddy 全家桶会话在云端，客观侧不接——
> 详细客户端清单与挂载位置见 `adapters/README.md`。

**漂移自检清单（逐字可用 prompt 块。以下整块原样内联进思考，只报命中类别、不逐条复述）：**

```markdown
<DRIFT_SCAN>
就近回顾最近约 10 轮，逐类判断“是/否”。只报命中的类别编号，不逐条复述。

1 指令退化 —— 会话早期立的规矩，现在守不住了
  □ 早先明确交代过的要求，我这轮没有照做
  □ 有约束我明明知道，却按自己的习惯做了
  □ 我在向用户索要他已经给过的信息

2 污染固化 —— 把错的当成对的
  □ 上次的结论或推断已经被证伪，我还在用它
  □ 同一个坑我掉进去第二次
  □ 用户纠正过我的说法，但我又犯了

3 焦点散失 —— 越写越偏
  □ 我的产出开始夹带与当前任务无关的内容
  □ 该收口的地方我在继续发散
  □ 明明做熟的部分，这轮质量反而下降

4 任务串味 —— 把几条线搅在一起
  □ 我把另一个任务的要求搬到了这个任务上
  □ 明显的小事上我挑错了工具或方法
  □ 我的产出同时混着两条线的口径

5 口径打架 —— 前后对不上
  □ 同一件事我在不同轮次给了不同说法
  □ 我对着互相矛盾的信息不知该信哪个
  □ 已经定过的事，我当成没定过又去问

数命中的**类别个数**（0–5）。不要数勾选框个数。
</DRIFT_SCAN>

<SCAN_RESULT>
VERDICT: HEALTHY | WATCH | DEGRADED | CRITICAL
HIT_CATEGORIES: [命中类别编号，如 2,5；HEALTHY 时留空]
TOP_RISK: [一句话，只说最要命的那一条]
NEXT_MODE: L0 | L1 | L2
</SCAN_RESULT>
```

**判档**：只认 §1.1 那张表。命中 0 → L0/`HEALTHY`；1（不含类别 1/2）→ L1/`WATCH`；2–5 → L2/`DEGRADED`；含类别 1 或 2 → L2/`CRITICAL`。

**输出纪律**：

- `HEALTHY` → **不出声**（不输出 `<SCAN_RESULT>` 块），但**照记 state**（§1.2）。
- `WATCH` → 回复末尾**追加 1 行**（§1.6 定稿文案），**不落盘**。
- `DEGRADED` / `CRITICAL` → **落盘交接文档**（§3），并把 `<SCAN_RESULT>` 块原样嵌进 `META`。

### 1.5 用户显式触发与 resume（零依赖路径）

**把这句话放到用户看得见的地方**（README / 团队约定）：

> 你只需要记住**两个词**：
> - **`交接`** —— 我产出一份交接文档，并告诉你新会话怎么接

### 1.6 sub-L2 询问行的定稿文案（L1 与临界区共用；⛔ 一字不改，不要临场自创）

```
提醒：<原因>。是否打包你定，说「交接」我出文档。
```

**呈现信封（2026-10-12 v2.3.1·防埋没）**：上行是**原稿**（判定与同稿契约的唯一锚，一字不改）。AI 在对话里转述提醒时必须套用固定三行信封——首行 `━━━ 🎒 baton 交接提醒 ━━━`，中行=原稿行（逐字），尾行 `━━━━━━━━━━━━━━━━━━`；催办行同信封、中行换为催办原稿。信封属呈现层，不改变触发判定与频控；⛔不许裸贴一行埋进段落（历史教训：单行提示易被忽略）。

`<原因>` = 触发本行的**那一条白话**：L1 取 `<SCAN_RESULT>` 的 `TOP_RISK`；临界区取 `packaging_advisory.reasons` 里对应那条。说不出具体原因就不出这一行（不编原因）。

规则（三条，全部硬性）：

- **不含术语**（不出现 DEGRADED / 症状 / 自检 / L1 这类词），**原因必须是白话**。
- **同一会话最多出现一次**（L1 与临界区合计）。
- ⛔ **不要声称“文档已放好”**——这一行不落盘，那样说是假的。
  （确实落盘的是 L2，L2 的指路文案见 §4 步骤 8。）

可选提醒 hook 的询问行与本行**同稿**（`hooks/baton_reminder.py` 的 `REMINDER_ASK_LINE`），两处必须一致。hook 自己的频控是 **1+1+静默**（最多 2 次、第 2 次换版，见 §7.1）——本行"同一会话最多出现一次"只约束**模型自产行**，两者不混算。

## 3. 交接文档固定 schema

文件名：`HANDOFF-<YYYYMMDD-HHMMSS>.md`（可选再带一个用户语言的短 slug，如 `HANDOFF-20260923-104500-登录超时.md`）。
落盘位置：`./handoff/`（相对目录；可用环境变量 `HANDOFF_DIR` 覆盖）。**不写进 OS 临时目录**——临时目录会被清、跨会话会丢、Windows 上还难找，不利于“分发给团队”。

### 3.0 交接的输入：下一棒要做什么

> **一句话定位：交接文档 = 现在的你，写给未来接棒者的一封信**——不是聊天记录备份，是给"未来的自己"的任务简报。信写给谁、他要干什么，决定信里留什么。

参考实现的核心不是"全量快照"，而是**面向既定下一任务的定向压缩**。所以：

- **用户在说“交接”时，可以顺带说一句“下一棒要做什么”**（自然语言即可，
  ⛔ **不依赖任何客户端专属字段**、不需要 `argument-hint` 之类的键）。
- **说了** → 据它**裁剪**：与这个用途无关的字段写 `none（与下一任务无关）`，**或整行删除**。
- **没说** → 输出**全集**，`META` 的“下一棒用途”写 `未指定`。
- ⛔ **空字段整行删除或写 `none`，绝不为填满而编。** 编出来的是污染源，不是信息。

**必填与裁剪**：`OPEN_QUESTIONS` / `META` / `CORE_GOAL` / `CONSTRAINTS` / `CURRENT_STATE` / `KEY_FACTS` / `ARTIFACTS` / `NEXT_STEPS` 恒必填；
其余字段按下一任务裁剪。

### 3.1 字段清单（骨架；逐字填写要求与完整模板见 `references/schema-完整模板.md`）

| # | 字段 | 必填 | 核心要求 |
| --- | --- | --- | --- |
| 1 | `OPEN_QUESTIONS` | ✅ | **⛔ 正文第一行。** `未答问题：<一句话>`；多条 `未答问题②：…`，**≤5 条**按“是否阻塞下一步”排序，每条标**在等谁**；没有则 `none`。“等用户拍板”的事不能让下一棒自己拍 |
| 2 | `META` | ✅ | 生成时间(ISO 8601)、档位、原因、**下一棒用途**、**路径基准**、平台（⛔ 不确定写 `unknown` 不编）；**交接链深度**（可选，默认 1——resume 后再交接时 +1；≥2 时接手确认须提示"本文档已是第 N 手转述，关键数字建议回溯原始产物核验"）；内嵌 `<SCAN_RESULT>`（HEALTHY 写 `VERDICT: HEALTHY` 一行） |
| 3 | `CORE_GOAL` | ✅ | 目标与验收标准，**引用用户原话、逐字**，不可改写为概括；**分叉任务可多条**（各带自己的 NEXT_STEPS） |
| 4 | `STAKES` | 裁剪 | 为什么急 / 不做后果 / 用户态度，**逐字引用原话**（“明早客户要看”）。丢了它下一棒会按正常排期——**丢的是优先级，不是信息** |
| 5 | `CONSTRAINTS` | ✅ | 会话内一切指令与偏好：风格/工具/流程/护栏，**逐字**一条一行、**每条带轮次或时间**；凡 不要/必须/仅/一律/记得/别/只用 开头的用户句一律收；互斥标 `⚠️ 后者覆盖前者（第 N 轮）`。⚠️ 压缩中最易静默丢失的一类 |
| 6 | `CURRENT_STATE` | ✅ | 已完成/进行中/未开始三段；首选**符号名+路径**，行号作辅标“截至 `<ISO>`，可能已偏移”；区分 `[已验证]` 与 `[仅推断]` |
| 7 | `WAITING_ON` | 裁剪 | **被阻塞**：在等谁、等什么、到了怎么继续。缺它下一棒不知前提未满足，会**直接开工撞生产** |
| 8 | `KEY_FACTS` | ✅ | 数字/日期/ID/人名/金额/版本/阈值/报错码/URL **+ 称谓与术语口径**，**逐字表格**（§3.2） |
| 9 | `DECISIONS` | 裁剪 | 已定决策 + **理由（理由必写）**；每条带轮次或时间。只写 what 不写 why 是硬伤 |
| 10 | `DISCARDED` | 裁剪 | 已弃路径 + 为何弃 + 何时弃；**必含“被用户否决的提案”**：标 `否决者=用户` 并逐字写理由。缺它下一棒会又提那个方案 |
| 11 | `ERRORS` | 裁剪 | 未解决错误，**报错原文逐字粘贴**，不要总结成“有个类型错误” |
| 12 | `ARTIFACTS` | ✅ | 有路径/URL → 只写路径、⛔ 不复制内容；无路径 → 逐字内联标 `[无路径]`（见 references） |
| 13 | `NEXT_STEPS` | ✅ | 下一步按依赖排序，可执行到“打开哪个文件、跑哪条命令” |
| 14 | `SUGGESTED_SKILLS` | 裁剪 | 写“用 X 能力做 Y；本端若以斜杠暴露即 `/x`”，⛔ 不写裸 `/x`、不假设必有 Skill 工具 |
| 15 | `UNVERIFIED` | 裁剪 | 你只是“以为”的断言，保留 ⚠️（§3.3）；确实没有写 `none` 并附“已逐条验证过 X/Y” |

### 3.2 逐字保留规则（本 skill 的第一优先级）

**逐字保留，绝不摘要、绝不四舍五入、绝不“约”：**

- 数字、金额、百分比、阈值
- 日期与时间戳（含时区/格式，如 `2026-09-23T10:22:16+08:00`）
- ID、issue/PR 号、commit sha、会话 ID、单号
- 人名、组织名、邮箱、包名、模型名
- 文件路径、行号、URL、环境变量名
- 版本号、报错码、堆栈里的标识符
- **用户原话中的关键句**（含否定词与限定词——“不要”“必须”“仅”这类词丢掉一个，语义就翻）

**依据（等级与适用范围必须连在一起读，⛔ 不要只抄数字）：**

- 受控保留基准（合成多轮对话，植入 KeyFact/Decision/Reminder/Insight 四类工件）上，**逐字锚定抽取** recall **97.5%**（摘要法 **19.0%**）、exact match **93.0%**
  —— ⚠️ **等级 B/E**：单一作者、**自建合成对照**（arXiv:2601.00821 **v1**，2025-12-23；2026-10-11 一手回源）；
  ⚠️ 该文摘要把 19.0% 标为 exact match，与其 Table 2（19.0%=recall、14.0%=exact）口径不一，**本 skill 以 Table 2 为准**；
  召回对象是植入的认知工件（约束/提醒只是其中一类），⛔ **不要外推到数字/日期/ID 的逐字保留**。
- 压缩后**仅约 17%** 的注入会话约束（SC）存活
  —— ⚠️ **等级 B（preprint，未经同行评审）**；17% 是**平均值**，随压缩器 / prompt / 长度 / 措辞 / 注入位置**剧烈变化**（arXiv:2608.11242，2026-10-11 一手回源）。
- **约束靠"搬运原文"存活，不靠摘要器理解**：压缩后**把 SC 原文逐字重新附上**，compliance 达 **93.5–99.7%**（三场景，其表2）、下游模型全数 **>98%**（其表10：98.3/99.4/99.9%）
  —— （arXiv:2608.11242，2026-10-11 逐表回源）——`CONSTRAINTS` 逐字搬运字段的直接实证。
- （2026-10-11 撤下）曾引「压缩到 50% 时压缩区召回 0–7% / grep 命中 82–93%」——**多轮检索找不到原源**，按 §3.3 UNVERIFIED 纪律撤下，不留数字；"有路径只写路径 + 定向 grep"仍是本 skill 的做法，只是不再引用量化出处。

**为什么这不是保守**：约束类与精确值的召回，摘要法是个位数到 20% 量级。**“原样留着”几乎总是比“摘要一下”更划算。**

**两条反直觉纪律**：

1. **"写进文档了" ≠ "能被看到"。** 关键词存活 ≠ 模型召回。所以关键约束与关键数字要**放在文档前部**，别埋在中段——相关信息出现在开头或结尾时模型表现最好、埋在中段时显著下降（Lost in the Middle，arXiv:2307.03172；这也是 `OPEN_QUESTIONS` 置顶设计的直接出处）。
2. **⛔ 不要用"再补一段保留摘要"来对冲丢失风险。** 直觉是"多留一层保险"，实际方向相反：往文档里堆得越多，单条信息分到的注意力越被稀释（与 context rot / Lost in the Middle 同向）。**对冲手段是减少总量，不是增加总量。**
   （2026-10-11 注：此处曾引「保留区越多召回越差（68% → 39%）」——回源核查**找不到原源**，按 §3.3 UNVERIFIED 纪律撤下，只保留方向、不引数字。）

**⚠️ “逐字”与“脱敏”的边界（契约层，必须讲清）**：

- 有一类值**既是凭据形态、又是业务标识**——例如“把结果发给 `a@b.com` 让他确认”里的邮箱。
  它属于本节的逐字清单（下一棒不知道发给谁就没法干活）。
- 处理办法（**两步，缺一不可**）：
  1. **先判用途**：这个值在上下文里是“**用来认证/解锁**的”，还是“**用来指认对象**的”？
     **后者一律逐字保留。**
  2. 只有前者才替换；替换时**必须**写成 `<REDACTED:类型｜原值用途：<一句话>>`，
     并保证文档里有一句 `已脱敏项的原值请回原会话查找，本文件不含原值。`
- ⛔ **替换不得无声**：接手方至少要能看出“这里原本有个值、它是什么类型、它承担什么作用”。
  **裸的 `<REDACTED>` 不合格。**

### 3.3 未验证断言必须显式降级

下一棒**会把这份文档当合同，不会复查**。因此：

- 凡是你**只是假设**的（“X 还没做”“Y 已完成”），一律写进 `UNVERIFIED` 段，并保留 `⚠️` 标记；⛔ 不要写成事实。
- 凡是你**没有实际跑过**的命令/结论，标注“未实测”。
- `CURRENT_STATE` 里区分 `[已验证]` 与 `[仅推断]`。

> 这是本类文档最贵的一类错误：一个被写成事实的猜测，会成为后续一切的假前提。

### 3.4 文档体积纪律 + 四级取舍序

交接文档本身就是**下一会话的初始上下文**。它越大，下一会话越容易重演位置效应与注意力稀释——context rot：输入越长性能越不可靠，且"定向只给相关信息"显著优于"全量塞入"（focused vs full prompts，research.trychroma.com/context-rot；2026-10-11 回源）。

**四级取舍序（冲突时按此裁决，⛔ 不要临场自己发明）：**

1. **未答问题 + 约束**（`OPEN_QUESTIONS` / `CONSTRAINTS`）：**必留、置顶**。
   这是压缩中最易静默丢失的一类（实证：压缩后仅约 17% 的注入约束存活）。
2. **精确值**（`KEY_FACTS` 的逐字清单覆盖的一切）：**必留**，但**一行一条、不写解释**。
3. **每条 why 压到一行**：`DECISIONS` 的“为什么”、`DISCARDED` 的“为什么弃”，
   **与结论那一行同级保护，⛔ 绝不砍**（砍了下一棒就会重走死路）。
4. **产物**：有路径的只留路径；**无路径的（标 `[无路径]`）不受裁剪**（§3.1.1）。

**边界条款（容易做错，单列）**：

- `DISCARDED`：**砍复现步骤，绝不砍“结论 + 理由”那一行。**
- `CURRENT_STATE`：砍过程描述，**不砍“符号名 + 路径 + [已验证]/[仅推断]”这一行**。
- 目标仍是最小的高信号集：**能砍的是叙述，不能砍的是精确值与他人做过的判断。**

## 4. 执行步骤（L2 一次 pass 内完成）

**全部折叠在同一次输出 pass 里。⛔ 不允许拆成“先自检、再交接”两轮模型往返。**

> ### ⛔ 顺序纪律：**不抢占用户当前这一轮**
> **先完成用户当前请求的最小闭环**，交接文档在同一次 pass 的**末尾**产出。
> 若当前轮是**纯问答、没有工作单元边界**，**推迟到下一个自然边界**。
> 用户要的是一句结论，不是一个 2000 字文档。交接是**附带产物**，不是当轮主题。

**进入本节的前提就是 L2 已判成立（§1.1）——打包是主动义务：命中即做，不等用户说「交接」。**
用户显式说「交接」只是 L2 的入口之一（§1.5），不是自动打包的前置条件。

0. **取裁剪输入**：用户是否说了“**下一棒要做什么**”？说了就逐字记下（**自然语言即可**，
   ⛔ 不要为此引入任何客户端专属字段）。没说就**输出全集**。见 §3.0。
1. **自检**：内联执行 §1.3 的 `<DRIFT_SCAN>`，得 `verdict` 与命中类别数。
2. **抽取**：按 §3.1 逐字段填充。抽取时对照 §3.2 的逐字清单，把数字/ID/日期/约束**原位照抄**。
   与“下一棒用途”无关的字段写 `none（与下一任务无关）` 或**整行删除**——⛔ **不为填满而编**。
3. **降级**：把你没验证过的断言移到 `UNVERIFIED`（§3.3）。
4. **无路径产物内联**：粘贴文本、未落盘代码段、口头确认的方案 → 逐字进 `ARTIFACTS` 并标 `[无路径]`（见 references）。
5. **落盘**（**首选路径**）：
   **用你自己的文件写入工具，直接写 `./handoff/HANDOFF-<YYYYMMDD-HHMMSS>.md`。**
   - ⛔ **不要把文档内容塞进 shell 命令或 heredoc**——含反引号或 `$(...)` 的内容会被
     **真的执行**（不只是截断，是**命令注入 + 静默改内容**），且失败形态通常是静默的。
   - 相对路径以当前 cwd 为基准；目录不存在就先建（doc 里 META 写上这个绝对基准，见 §3.1 第 2 项）。

   **然后（可选，脚本可用时）跑后置扫描 + 就地脱敏**：
   ```
   python3 scripts/handoff.py --scan        --input ./handoff/HANDOFF-<ts>.md
   python3 scripts/handoff.py --redact-file ./handoff/HANDOFF-<ts>.md      # 有命中时；需要时加 --pii
   ```
   **⛔ 脚本是便利设施，不是前置依赖**——没有脚本也必须能完成交接；此时脱敏由你按 §5 的契约执行。

   ⚠️ **不要**用 `handoff.py --write --input -`：无管道时它会**挂起**；用 heredoc 未加引号
   会让 shell **真的执行**文档里的内容。要走脚本落盘这条路，就用
   `--write --input <已存在的文件>`（**次要路径**，注意它会在磁盘上留下一份明文草稿）。
6. **维护 `LATEST` 指针**：写 `./handoff/LATEST`，内容一行 = 刚落的文件名。
   （`--write` 会自动做；手写路径时自己补，否则新会话的 `resume` 只能按 mtime 猜。）
7. **静默记账**（可选，脚本可用时）：见 §1.2 的 `--log` 命令行。
   ⚠️ 写文件不算出声——它不破 L0 静默。这是“该触发没触发”唯一的事后凭据。
8. **输出指路**（≤3 行，**用绝对路径**）：
   ```
   交接文档：/abs/path/handoff/HANDOFF-20260923-104500.md
   新会话接法：把上面这个路径发给我，或直接说 resume。
   未答问题：<primary 未答问题一行>
   ```

### 4.1 交付纪律（重要）

- **指向文件路径，不要把交接内容贴进 shell 命令或引号里。** 含反引号或 `$(...)` 的内容被塞进命令时会损坏，而且**失败形态通常是静默截断而非报错**——下一棒会带着残缺简报开工。
- 用户可能要求你复述路径，**先记住路径再继续**。
- **行号会腐烂**：交接后别的 agent 改几行，行号就偏了。所以定位首选**符号名 + 路径**，行号只作辅并标“截至 `<ISO 时间>`，可能已偏移”（§3.1 第 6 项）。
- **跨端提醒**：若下一次会话可能不在一小时内、或会换 harness / 换目录：提醒用户把交接文档复制到持久位置（仓库内或团队共享盘），并说明文档内指向的其他临时文件也会一并失效。文档自身也要写死路径基准（`META` 的“路径基准”）。

## 5. 脱敏（契约 + 实现）

**先立契约：脱敏的对象是「凭据」，不是「数字」。**
⛔ **绝对不要动的**：业务数字、金额、日期、issue/PR 号、commit sha、包名@版本、文件路径、行号、单号、版本号、报错码。**改坏这些等于直接击穿第一优先级。**

### 5.1 替换标记的形态（⛔ 不得裸替换）

```
<REDACTED:类型｜原值用途：<一句话说明这个值在上下文里干什么>>
```

并在文档里保留一句：`已脱敏项的原值请回原会话查找，本文件不含原值。`

脚本机械替换时“原值用途”写 `见原会话`；**你能说清用途时，把它改成一句话**。

> 完整三级替换判定（高置信形态 / 强凭据键 / 弱凭据键）、PII 规则与落盘后扫描实现，见 `references/脱敏规则表.md`。

### 5.5 ⛔ 不许做的三件事

1. **不要**因为“看到一串像密钥的字符”就替换——那会改坏业务 ID / commit sha。
2. **不要**用“更安全”当理由扩大规则。本实现有意偏向「**宁可漏替换，也不改业务值**」。
3. **不要**把 `<REDACTED>` 裸着写进文档——必须带类型与用途（§5.1）。

### 5.6 已知薄弱（硬要求，不是客套）

脱敏是**正则 + 判断**，不是形式化保证。会漏的形态：全小写自定义 token、
短于 20 字符的弱键值、非标准凭据格式。
**所以落盘后请你自己再扫一眼**——这一条是硬要求。

## 6. 反模式（⛔ 不要做）

| 反模式 | 为什么错 |
| --- | --- |
| 每轮都输出“上下文体检报告” | 破静默默认；仪式化输出本身是噪音。L0 无异常不出声（但**照记 state**） |
| 自检拆成独立一轮模型往返 | 用户明确否掉：不丝滑。必须折叠进交接文档那一次 pass |
| **L2 抢掉用户当前这一轮** | 用户要一句结论，拿到 2000 字文档。**先完成最小闭环，交接放末尾；纯问答轮推迟到下一个边界** |
| 把交接文档写进 OS 临时目录 | 会被清、跨会话会丢、Windows 上难找。默认用 `./handoff/` |
| 把交接内容粘进 shell 命令 / heredoc | 含反引号 / `$(...)` 会被**真的执行**（命令注入 + 静默改内容），不只是截断 |
| 复制**已有路径**的产物内容进文档 | 文档膨胀 + 两处会漂移。**按路径引用** |
| **省略无路径的产物** | 粘贴的需求原文、未落盘的代码段**没有别的地方可去**，漏掉就是彻底消失。标 `[无路径]` 逐字内联 |
| 把数字/日期/ID 摘要成“约 42k”“上周” | 摘要法对精确值的召回是个位数到 20% 量级 |
| 用“再补一段保留摘要”对冲丢失 | 保留区越多召回越差（注意力稀释）。**减少总量** |
| 把猜测写成事实 | 下一棒当成合同、不会复查，假前提会污染后续一切 |
| 编一个 token 数当“已测量”上报 | 宿主通常无指标；**猜的不能报成测的**（数工具调用次数**不算**猜 token） |
| 断言“压缩 ≥3 次就该交接” | 该维度**无任何来源**给出阈值。要用必须自标为启发式 |
| 承诺“我会在压缩前自动保存” | 本 skill **无法执行压缩、无法拦截压缩**。做不到就别说 |
| 只写 what 不写 why | 本类文档被反复批评的硬伤；下一棒会重走你已否决的路 |
| **为了“填满 15 个字段”而编内容** | 与下一任务无关的字段写 `none` 或整行删除。**编出来的是污染源** |
| **L0/L1 不出声就当没发生、不留痕** | 该触发没触发将**无从查证**。**静默 ≠ 不记账** |
| 声称自检“成本约等于零” | 未测量的量级断言，与 §0 诚实纪律冲突。只能说“不新增模型往返” |

## 7. 主动提醒 hook（可选增强件，默认不挂）

baton 核心**不依赖任何 hook**，纯调用式即可工作。本节约定的是一个**可选增强件**：宿主支持 hook 事件时，可由脚本在会话节点客观对撞，发现"该交接却没交接"时主动提醒一句；没有它，核心功能不打折。

### 7.1 组件与安装

| 文件 | 角色 | 失败语义 |
| --- | --- | --- |
| `hooks/baton_reminder.py` | 运行时：在事件（WorkBuddy 实测挂 `UserPromptSubmit`，其余推荐 `Stop`）被调用，读客观 + 自报账（**streak 取值回正**：自报优先、客观兜底，见下），**双分支**输出——**L2 级信号 → 催办一行**（指示直接打包，§1.1）；**sub-L2 软信号/自报失真 → 询问一行**（是否打包用户定，§1.6 同稿）；**1+1+静默频控 + 退出通道 + 埋点**（见下） | **fail-open**（异常/超时静默，不阻塞 agent） |
| `hooks/install_reminder.py` | 安装器：探测 provider、信任门、改 settings、幂等 | **fail-closed**（任何失败保持原配置） |
| `hooks/uninstall_reminder.py` | 卸载：移除 hook 标记、清状态 | **fail-closed** |
| `hooks/_baton_common.py` | 内部共享工具（路径/状态/信任门/跨平台） | — |

安装：`python3 hooks/install_reminder.py [workspace]`（先 `--dry-run` 预览）；
卸载：`python3 hooks/uninstall_reminder.py [workspace]`。

**触发源（v2.3.0 回正）**：

- `streak` 取值 = `state.json` 自报**优先**，**缺失时用客观值**——`baton_tick.py` 由会话事件时间线切工作单元算出（时间间隔分段，纯聊天段不计），输出 `streak_source` ∈ `{"self_report", "objective"}`。⛔ v2.1.x 曾绑死自报账，无自报账的普通会话完全不触发（v2.1.0 设计-实现脱节的根因，v2.3.0 修复）。
- 双分支与 §1.1/§1.3 同一套阈值：streak ≥2 → 询问行；≥3 → 催办行（`l2_objective_hit`）；体量轴（≥15 轮 / ≥60 分钟）**只进询问行**。阈值全部自标**工程启发式**（依据：证据报告 2026-10-12，学术查无）。

**频控 1+1+静默（v2.3.0）**：

- 第 1 次出声后记账；**第 2 次**需同时满足「距上次 ≥ **30 分钟**」且「信号增强（streak 增加）」，**换版文案并点明具体信号**（"已连续 N 个工作单元未落盘"）；**两次后本会话静默**。
- 检测到交接文档落盘（`HANDOFF_DIR/LATEST` 更新晚于上次提醒）→ **重置**计数，进入新循环。
- 频控状态：`<workspace>/.baton-state/<ws-hash>/<agent-id>/reminder_state.json`（600）。

**退出通道与埋点（v2.3.0）**：

- 每条提醒行末尾附「**（说「别提醒」本会话不再提醒）**」；用户说了，**agent 执行** `python3 hooks/baton_reminder.py --mute <workspace>` 写 per-session 关闭 flag（`--unmute` 恢复）。⛔ hook 自身不读 prompt——措辞识别由 agent 完成，P0-γ 隐私边界不变。
- 状态文件记三个**纯计数**：`exposure`（提醒曝光）/ `handover_conversion`（曝光后发生交接）/ `ignore`（曝光被越过未转化）；⛔ **只计数，不记 prompt**。
- **验收口径**：忽略率 = `ignore / (ignore + handover_conversion)`，**>70% 应收紧触发**（70% 为 Copilot 采纳率量级的工程推测，待埋点数据收敛）。

### 7.2 状态根与隐私

- 状态根 = `<workspace>/.baton-state/<ws-hash>/<agent-id>/`，权限 `700`。
- ⛔ **不落 skill 包内**（只读 / 共享 / 版本控制目录不可写且会污染分发）；`.baton-state/` 进 `.gitignore`。
- 标记：`installed`（唯一安装判据）；`offered` 由呈现选择块的一方写入，安装器默认"否"时**不写**。
- 频控状态 `reminder_state.json`（v2.3.0）：`count / last_at / last_streak / muted` + 三计数 `exposure / handover_conversion / ignore`，权限 `600`；⛔ **只记计数与时间戳，不记 prompt**。
- 台账最小化：仅 `ws-hash / 事件 / 时间戳`；⛔ **不记 prompt 全文或摘要**。

### 7.3 安全约定

- **prompt 传输（P0-γ）**：命令串中不出现 `--prompt`；运行时 hook 不接收 prompt 内容（用位置参数 / stdin / JSON / 受控环境变量；明确转义、长度上限、脱敏）。
- **信任门（P0-ε）**：写 settings 前校验 skill / tick / 解释器 / settings 路径的 owner、权限、ACL；任一可被他人写入/替换 → 拒绝写入并退出非零。
- **完整性自检**：`baton_reminder.py --selfcheck` 的期望 hash 必须来自**外部签名 / 发布清单 / 只读信任源**（`--manifest` / `BATON_EXPECTED_HASH`）；无外部锚点时明确声明"仅完整性提示，非安全边界"，杜绝同目录 hash 自证。
- **执行面（P0-η）**：`BATON_SCRIPTS` 回退仅在显式、绝对、受信任时启用，否则取消。
- **超时（P1-7）**：hook 条目带 `timeout`；运行时设快速预算（`BATON_TIMEOUT`），不阻塞 agent。
  ⚠️ 例外（2026-10-11）：provider 的**实测**条目形态不含 `timeout` 时按实测写（如 WorkBuddy `UserPromptSubmit` 条目仅 `type/command`，见 references/TESTED.md §1）——快速预算由运行时 `BATON_TIMEOUT` 承担，⛔ 不为对齐本条而伪造条目键。

### 7.4 生产-消费契约（P0-β）

状态/文档的写入方与读取方必须落在同一路径，否则自检静默失效（v0.1 曾因此恒空）：

| 写入方 | 产物 | 读取方 |
| --- | --- | --- |
| `handoff.py --log`（首选）/ 模型手写 | `HANDOFF_DIR/state.json`（默认 `./handoff/state.json`） | `baton_tick.py read_handoff_state`（同解析：`$HANDOFF_DIR` > `<ws>/handoff`） |
| 模型直写 / `handoff.py --write` | `HANDOFF_DIR/HANDOFF-*.md` | 下一棒 / `resume` |
| 落盘成功 | `HANDOFF_DIR/LATEST` | `resume` 解析、`handoff.py --latest` |

> ⛔ 分发包**删除**旧隐藏目录回退（三方一致），故 `grep '\.handoff' scripts/ README.md adapters/` 应为 0（CHANGELOG 中的历史描述除外）。
>
> ⚠️ **cwd==ws 约定（2026-10-11 补）**：上表的读取方按**两套基准**定位 state——`baton_tick.py` 按**传入的 workspace 参数**（缺省 cwd）找 `<ws>/handoff/state.json`；`handoff.py --log` 按**当前 cwd** 解析 `./handoff/`。两者要对上，须约定**运行时 cwd == workspace**（或统一显式设 `HANDOFF_DIR`），否则自检静默失效（v0.1 曾因此恒空，同一教训）。

### 7.5 首次询问、卸载、升级与迁移

- 首轮必检（2026-10-12 v2.3.1）：skill 每次会话触发时先跑 `python3 hooks/install_reminder.py --dry-run`（只读预览·fail-closed）；未挂且 `offered` 不存在 → 每 workspace **提示一次**安装询问（per-ws key 双轨，保留"永不询问"路径）；已挂/已拒 → 静默。安装动作仍需用户确认（信任门 P0-ε 不变），本条只把"检查"从可忽略升级为必做。
- 升级：同标记的旧条目在**备份后替换**（幂等，不跳过）。
- 迁移：Python 解释器或 skill 路径迁移后，旧 hook 会变孤儿；重跑安装器或用 `uninstall_reminder.py` 清理后重装。
- 不支持 hook 的宿主（如豆包办公端）：安装器打印手动片段并记录"未挂载"，可忽略——核心不依赖 hook。
