# checklist.md — 复查扩展清单（康复复查必查，不止跑评估器）

> 用法：复查阶段，在评估器全量重跑之外，逐项过本清单。每项都要**证据**（命令输出/文件路径/实测记录），「检查过」≠「证据在」——存在≠完成。
> 分三层：静态 10 项（S1-S9 + S10 分享泛化）→ 五要素齐全性 → 运行时实测 4 项。任何一项不过，记录进修复履历，按分级处理。

---

## 一、静态 10 项

### A. 4 项基础反哺自查

| # | 检查项 | 怎么查 | 判定标准 |
|:--:|:---|:---|:---|
| S1 | **frontmatter 合规** | 读 SKILL.md 头部；`head -5 SKILL.md` | `name` / `description` / `version` 三字段齐，description 含触发词且含 NOT for 边界 |
| S2 | **行数 <500** | `wc -l SKILL.md` | ≤500；超了把参考性内容拆进 `references/`，SKILL.md 留决策骨架（同时触发 mechanism.md ⑦特例：p7.references_extruded 升基本型） |
| S3 | **触发实测** | 构造三类请求实测（见下「运行时实测」第 2 项） | 该触发→触发；边界内→触发；范围外→明确拒绝/指引去处 |
| S4 | **依赖声明** | 读 README 或文件头 | 脚本语言/版本/第三方包/外部命令全部声明；无声明=不过 |

### B. 5 项失败模式扫描（修 skill 常见翻车点）

| # | 失败模式 | 症状 | 怎么查 | 判定标准 |
|:--:|:---|:---|:---|:---|
| S5 | **代码围栏输出陷阱** | 命令示例包在围栏里，模型把围栏语法/提示符当字面输出复制，执行必错 | `grep -n '```' SKILL.md` 定位围栏；抽查围栏内命令能否脱离围栏直接跑 | 围栏内是纯可执行命令，无 `$` 提示符混入、无 `（示例）` 类占位伪代码；有说明「复制运行」或标注了不可直接跑的 |
| S6 | **被动推迟** | 用「当用户要求时 / 如有需要 / 可以」触发动作，模型无限推迟不干活 | `grep -nE '当.*时|如有需要|如果需要|可以' SKILL.md` | 关键动作有「必须/默认/先」类主动指令，不只靠被动条件 |
| S7 | **重复模式** | 同一校验/同一逻辑在多个脚本或段落重复写，改一处别处忘 | `grep -c '同一段关键命令' -r scripts/`；对比重复段落 | 重复逻辑收敛为单脚本/单定义，或显式声明多份副本及同步方式 |
| S8 | **重复指令** | 同一指令多处表述不同（如「不许跳过」vs「可以省略」），行为冲突 | 语义扫描：同一约束 grep 到的所有位置逐一读 | 同一约束表述一致，无互相矛盾；冲突处有仲裁（见 mechanism ⑤conflict_arbitration） |
| S9 | **模糊占位符** | 用「xxx / TBD / 待补充 / 举个例子」占位符没填，模型照抄进产物 | `grep -rnE 'xxx|TBD|待补充|TODO|占位' SKILL.md README.md references/ scripts/` | 0 命中；命中处是真示例标注（明说「示例」）或已填实 |
| S10 | **分享泛化（v1.1.1）** | 包要分享给别人——内部称呼（人名/专属 skill 名/内部文档名/品牌名/「领导」「任务书」类词）留在 description/NOT for/正文/案例 = 噪音 | `grep -rnE '<人名>|<品牌名>|本书|本任务|任务书|领导' SKILL.md README.md references/ scripts/`（按实际内部词替换） | 0 命中；命中处若是通用词（用户/维护者/需求文档）则合规；description 的 NOT for 用通用排除（「从 0 设计新 skill」），不指向私有 skill |

## 二、五要素齐全性（skill 骨架五件套，缺一即接诊不合格）

| 要素 | 检查点 | 判定标准 |
|:---|:---|:---|
| **触发** | description 触发词 + 边界 | 触发词能覆盖用户口语（含变体）；NOT for 排除范围；「什么时候不触发」写清 |
| **步骤** | 流程分步 | 有 `**N 步骤名**` 连续编号 ≥3；每步一个可验证动作；步骤间有产出物/检查点（对照 mechanism ④） |
| **输出格式** | 产物格式声明 | 每步/整体产出物格式明确（文件名/表格/JSON 结构），有示例；「产出物：xxx」式声明 |
| **边界** | 范围声明 | 明确接什么/不接什么；不接的给正确去处（如「从 0 设计新 skill」明确不接诊，指向专职创建流程） |
| **测试用例** | 验收可执行 | 有可执行的验收命令或判定标准（grep/diff/exit/断言），不是「检查确认」类模糊描述 |

## 三、运行时实测 4 项（真跑一遍，不是读文档）

> 实测记录写进本次康复的 `.goal/` 工作记录（如 `trigger-test.md` / 履历「实测」列），附命令与输出。

| # | 实测项 | 怎么做 | 判定标准 |
|:--:|:---|:---|:---|
| R1 | **输入输出格式** | 给 skill 一个典型输入，走完整流程，看产物 | 产物格式与 SKILL.md 声明一致；数值/字段/文件名无漂移 |
| R2 | **没触发 / 误触发** | ①触发词变体（口语化、简写）实测能否触发 ②范围外请求（如设计新 skill）实测 | 该触发→触发且走对流程；范围外→拒绝或指引去处，不硬接 |
| R3 | **跳步骤** | 故意跳过某步（如不跑评估器直接改）实测 | skill 有强制闸门（「诊断先于治疗」类死规矩）拦截，或明确警告后继续；无拦截=不过 |
| R4 | **卡死循环** | 连续失败/超时场景实测（连败 N 次、回滚条件） | 有熔断/止损定义（连败 3 次换项、满轮即停），实测不无限重试 |

## 四、类别完整性复查（充分性，防「评估器没点名就跳过」）

> 评估器只判「必要条件」（有没有），判不了「全不全」。治疗是否彻底，看**类别完整性清单**（`references/completeness.md`）——按 skill 类别穷尽列出「这类该有的」，逐项核对，**缺口清零才算达标**。

| # | 步骤 | 判定 |
|:--:|:---|:---|
| C1 | 按 `completeness.md` 分类规则判断该 skill 类别 | 分类正确（特征词命中）|
| C2 | 过该类完整性清单，每项标 脚本化✓ / 命令化✓ / 显式留AI✓(理由) / ❌缺口 | 无 `[❌缺口]` 残留 |
| C3 | 完整性缺口 vs 修复履历逐条对照 | 处方里的缺口全部有修复记录，无「诊断了没治」|
| C4 | 评估器满分但完整性有缺口时 | **不算达标**——继续修缺口，不许「满分=收工」|
