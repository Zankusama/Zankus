# cross-review.md — 评审层交叉验证流程（子代理互审 + 仲裁）

> 模块 B（评估器深化）新增：把评审层复核从「执行者自判」升级为「子代理交叉验证」。
> 适用：评估报告中的**评审层判定项**（alternatives_considered / ban_with_alternative / desc_consistent）——这些是关键词启发式默认判定，脚本只收集证据，结论必须经交叉验证才能定案。
> 借鉴：53ai 多模型交叉验证流程（独立评估 → 交叉互审 → 仲裁 → 共识度）；配套审计清单见 `.goal/review-audit.md`（模块 D 产出，列了每项的误判场景）。

## 五步流程

### 第一步 · 准备证据

执行者（评估报告生成方）整理评审层判定所需的证据包：

- 评估报告原文（含评审层 3 项的默认判定 + 脚本证据）
- 被评估 skill 的 **SKILL.md 全文**（引用依据，不许只看报告摘要）
- 判定点清单：每项标出「脚本怎么判的」——命中的关键词/正则

### 第二步 · 独立评估（两个以上子代理）

- ≥2 个子代理**互不通信**，各自独立读 SKILL.md + 报告，对每个评审层判定项给结论：**过 / 不过**
- 每个结论必须附**引用**：`SKILL.md 第 N 行「原文摘录」→ 结论`（不许空泛说「感觉不对」）
- 各自输出独立评估表，互不讨论

### 第三步 · 交叉互审（引用证据质疑）

- 子代理 A 拿子代理 B 的评估表，逐项用 SKILL.md 原文质疑：
  - 质疑必须是**引用驱动**：「你判『过』，但第 N 行只出现了关键词 X，没有 Y（选择理由），不算真 Alternatives」——不许「我觉得你不对」这种无引用质疑
  - B 同样审 A；双方可补充证据，但**不得改自己的原始结论**（保留分歧现场）

### 第四步 · 主模型仲裁

- 主模型（康复师）收集所有评估表 + 互审质疑，逐项定案：
  - 两方一致 → 直接采纳
  - 两方分歧 → 仲裁：以「SKILL.md 实际内容」为准绳裁决，给出裁决理由（引原文）
  - 仲裁后可要求补测（如跑一次 run_runtime_tests.py 或重新读某段）

### 第五步 · 出共识度报告

- 输出报告：每项判定 = 独立评估结论（A/B）+ 互审分歧 + 仲裁结论 + **共识度**
- **共识度三档**（明确标注）：
  - 🟢 **高共识**：两方独立结论一致且互审无分歧 → 判定定案
  - 🟡 **中共识**：两方一致但互审提出过可澄清质疑（已澄清） → 判定定案但记录质疑
  - 🔴 **低共识**：两方结论分歧、仲裁裁决 → 判定以仲裁为准，标记「需人工终审」
- 低共识项必须进报告「待人工终审」清单，不许悄悄吞掉

## 汇报格式（子代理按此输出）

```
## 独立评估（子代理 {代号}）
| 评审层项 | 结论 | 引用（SKILL.md 行号+原文） |
|:---|:---:|:---|
| alternatives_considered | 过/不过 | L{行号}「{原文摘录}」→ {理由} |

## 交叉互审质疑
- 对 {子代理代号} 的 {判定项}：L{行号}「{原文}」…（质疑理由）

## 仲裁结论（主模型）
- {判定项}：定案 过/不过（理由，引原文）
- 共识度：🟢/🟡/🔴 + 说明
```

## 示例（alternatives_considered）

- 子代理 A 判「不过」：L65「## Alternatives Considered」段存在但只有标题无正文——关键词命中，内容为空，不满足「真列了替代」
- 子代理 B 判「过」：L65 标题存在即视为声明过
- 互审：B 质疑 A「标题存在怎么不算」；A 引 L66-68 全文无替代内容回应
- 仲裁：以 SKILL.md 实际内容为准——段标题下有正文但只有「考虑过 A、B，选 A」无选择理由 → **不过**，共识度 🔴 低共识（需人工终审：若正文补选择理由则翻盘）

## 死规矩

- 交叉互审必须引用 SKILL.md 具体内容（行号+原文），**不许空泛质疑**
- 共识度三档（🟢/🟡/🔴）必须标注，低共识必须进「待人工终审」
- 独立评估阶段子代理**互不通信**，防止锚定
- 本流程只定案评审层判定项；机器层判定（可正则硬判）不在此流程内
