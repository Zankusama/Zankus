# skill-rehab — Skill 康复师

把「修 skill 像打补丁」固化成康复流程：**诊断 → 处方 → 治疗 → 复查 → 交付**。
任意风格、任意人写的已封装 skill，都能被系统化修好，而不是哪疼贴哪。

## 这是什么

- **诊断**：内置评估器 `scripts/skill_eval.py`（8 原理 · 双层评估 · 100 分），机器层硬判 + 评审层证据收集
- **处方**：`references/mechanism.md` 按机制给修法（8 原理 × 症状 × 分级 × 2-3 修法选项），不按格式给——不同风格 skill 不会被修成同一模子
- **治疗**：默认轻量 check（修一验一）；复杂 skill 重度跑（每项过全套闸门，用户选）
- **复查**：全量评估 + 扩展清单（frontmatter 合规 / 行数 <500 / 触发实测 / 依赖声明）
- **交付**：修复 diff + 修复履历（每项为什么修 → 对应机制）

## 内置评估器（自带诊断器）

- **版本**：`scripts/skill_eval.py`（`__version__ = "3.0.1"`；v3.0.1 修 p9 假阳性：min_fence_count 2→1 + 模糊占位符关键词「占位符?」→「占位符\b」精确匹配；自举 100/100 S）
- **v2 → v3 改动**：8 原理 item weight 按比例缩到总和 10（v2 20/12/15/13/15/10/5/10 → v3 各 10）+ 新增 ⑨失败模式防御（5 姿势机器层硬判）+ ⑩五要素齐全性（5 要素机器层硬查）；总分 100 不变
- **来源**：本包内置（v2 原拷贝自 Skill 架构规范目录，v3 升级为康复师自维护，sha256 跟踪）——升级走下方版本管理流程
- **校验**：sha256 `6a2091e30ec8...`（v3.0.1 当前）
- **自检**：`python3 scripts/skill_eval.py --self` 全过（10 原理层齐全 / 总分 100 MECE / 机器 90 + 评审 10）
- **回归**：`./scripts/guard.sh verify` 通过（升级后 verify 会失败是预期，提示重 snapshot）
- **实跑分数**（v3.0.1 / 2026-08-03）：skill-rehab 100/100 S | leader-translator 100/100 S（v3.0.0 是 96，关键词修复受益）| second-brain 80/100 A

### 评估器版本管理流程（v3 起，取代 v2 的「只读 + 改共享评估器须确认」）

1. **改前**：`./scripts/guard.sh snapshot` 冻结当前 sha256（v3 baseline 已冻结）
2. **改中**：自由改 `scripts/skill_eval.py`（PRINCIPLES / ev_p* 函数 / 报告）
3. **改后**：`./scripts/guard.sh check`（跑 --self）+ `./scripts/guard.sh verify`（应 fail = 改了 = 预期）+ 自举回归 ≥90
4. **正式发布**：`./scripts/guard.sh snapshot` 重置基线为新版本
5. **本文件**：更新版本号 / sha256 / 实跑分数
6. **禁止**：不 snapshot 改评估器 = 静默事故，自举分失去意义（死规矩 1）

### 共享评估器 vs 内置评估器（v3 起区分）

- **共享评估器**（`Skill 架构规范目录/skill_eval_v2.py`）：仍是 v2 不动，v3 升级在康复师内置份里做
- **内置评估器**（本包 `scripts/skill_eval.py`）：v3 起康复师自维护，跟随康复师版本号走
- **同步原则**：v3 不再 1:1 同步共享评估器，共享评估器升级由维护者单独启动

## 安装

### WorkBuddy（本机 skills 安装目录）

把本包整个目录放进 skills 安装目录（`~/.workbuddy/skills/`，目录名 `skill-rehab`），或建目录软链接指向权威源。装完在对话中触发「修skill / 康复师 / skill体检 / 诊断skill / 打磨skill」即可接诊。

### Claude Code（`.claude` 目录）

把本包整个目录放进 Claude Code 的 skills 目录（`~/.claude/skills/`，目录名 `skill-rehab`）。

## 使用（五步）

1. **诊断**：`python3 scripts/skill_eval.py --base <技能目录> --skills <skill名> --output <报告目录>`（`<>` 为需替换参数，别照抄），读 8 原理得分 + 未过项
2. **分级处方**：未过项逐条查 `references/mechanism.md`，按 Kano 五类分级（基本型必改 / 期望型建议 / 兴奋型备选 / 无差异跳过 / 反向红线）
3. **治疗**：默认轻量 check，只修基本型（死规矩 9），修一验一；复杂 skill 先列改动清单给用户确认
4. **复查**：全量重跑评估 + 完整复查清单（静态 9 项 + S10 分享泛化 / 五要素 / 运行时实测 4 项，见 `references/checklist.md`）
5. **交付**：出修复 diff + 修复履历（为什么修 → 对应机制）

## 运行依赖（依赖声明）

- **python3**（仅标准库：os/re/json/sys/argparse/datetime，无第三方包）
- 外部命令：无（评估器自包含）
- 评估器版本：见上「内置评估器」节

## 边界

- **NOT for 从 0 设计新 skill**（本流程只修已封装 skill）
- **NOT for 文案/合规审核类任务**（各有专职流程）
- 包内零绝对路径（以主目录开头的路径命中 = 0），脚本一律相对路径引用，可整包分享
