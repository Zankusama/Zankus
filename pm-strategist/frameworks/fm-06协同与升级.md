# fm-06 · 协同与升级：跨部门确认 + 升级路径

> 一句话：PM 不独自扛 B 类决策——哪些决策必须谁确认、口径怎么对齐、谈不拢往哪升级，本文是机制支撑文件。
> 来源：RACI——通用项目管理责任分配工具（来源：PMI PMBOK 责任分配矩阵实践）；升级路径——体系内自研通用化改写（不编造来源）。

## 适用时机

- S4 定价与盈利：最终定价决策需跨部门确认（财务/销售/渠道/管理层）——本文是"需跨部门确认"的机制支撑
- S5 上市 GTM 策略：最终上市决策需跨部门确认（销售/市场/供应链/管理层）
- S2 产品线组合规划：组合调整牵动多部门资源时，确认与升级机制同样适用
- 条件：决策影响面超出 PM 职责边界（改别人的预算/目标/承诺），或 DR 拍板前置条件含"跨部门确认"
- 不适用：A类场景内 PM 职责范围内的常规决策（自行拍板+落 DR 即可，套 RACI=仪式化）

## 框架内容

### 一、跨部门协同：RACI 口径

- R 负责（Responsible）：干活的人，PM 常态在此
- A 拍板（Accountable）：最终担责者，每个决策有且只有一个 A
- C 被咨询（Consulted）：意见必须被听取，但不拍板
- I 被知会（Informed）：结果送达即可，不参与过程

**B类场景的 RACI 口径**（PM 不当 A）：

| 环节 | PM | 跨部门 | 管理层 |
|------|----|--------|--------|
| S4 定价：测算与建议 | R（出账/出建议） | C（财务/销售/渠道：口径与异议） | A（最终拍板） |
| S5 上市：GTM 方案与排期 | R（出方案/组织对齐） | C（销售/市场/供应链：可行性承诺） | A（最终拍板） |

- 用法：PM 产出建议与测算（R），跨部门作为被咨询方逐家收口（C），管理层是唯一 A
- C 类意见必须留痕：每家的异议/承诺写进 DR 的反方意见与风险字段，不许口头吸收
- B类标注（决策记录里逐字保留）：最终定价决策需跨部门确认（财务/销售/渠道/管理层）；最终上市决策需跨部门确认（销售/市场/供应链/管理层）

### 二、升级路径（PM 职责外向谁升级）

按"决策影响谁，就升级到谁"逐级走：

1. 平级对齐（第一站）：先与受影响部门负责人对口径，能对齐就不升级——多数分歧源于口径不同而非利益冲突
2. 直属上级：影响本部门内资源/目标，或平级对齐失败 → 升级给自己的上级，带齐 DR 与分歧点
3. 跨部门上级对上级：两个部门各自上级谈，PM 负责供给材料（数据/选项/反方意见），不越级传话
4. 管理层拍板（终审）：🔴 不可逆 + 跨部门僵持 + 影响公司级资源 → 提交管理层，按 RACI 的 A 角色裁决
5. 升级不是失败：带着"已对齐/已分歧清单"升级是专业；拖着不升级把决策拖黄才是失职

**升级件三要素**（提交给上级/管理层时必须齐）：
- 分歧点陈述：谁在哪个字段上不同意（引用 DR 字段，不做人身归因）
- 选项与建议倾向：≥2 选项含不做/维持现状，PM 给推荐倾向与权衡（不出方案只给建议，联动行为准则）
- 时间点：多久之内必须定，不定会损失什么——没有截止时间的升级会被无限搁置

### 三、确认机制（B类"需跨部门确认"的操作定义）

1. 确认前置：DR 已含 9 字段草案+三问结论（fm-05）+6 风险维度过筛（法规/市场/竞争/供应链/财务/组织）
2. 确认清单：把"需跨部门确认（××/××/××/管理层）"拆成逐部门逐人的确认清单，每格写：要确认什么/异议记录/结论（同意/有条件同意/反对）
3. 确认留痕：清单与最终决策一并归档进 DR；"有条件同意"的条件写进风险与假设清单
4. 确认时效：给出确认截止日；到期未反馈=升级动作触发（进入升级路径第2站），不许默默等待

## 用法步骤

1. 判类别：本决策是否 B类/是否越出 PM 职责——检查点：越界决策不许自行拍板
2. 写 RACI：一页纸标出 R/A/C/I，A 唯一——检查点：出现两个 A 或 A 缺位=重写
3. 收口 C 类意见：逐部门确认并留痕——检查点：每家结论可追溯（同意/有条件同意/反对+理由）
4. 拼升级件：若对不齐，按三要素组装升级件——检查点：分歧点/选项建议/时间点齐
5. 逐级升级：从平级开始逐级走，不越级、不跳步——检查点：每级留一句升级记录
6. 终审落字：管理层拍板后更新 DR 决定/依据/状态，状态推进为已定——检查点：`python3 "$SKILL_DIR/scripts/check_output.py" <输出文本文件>` 退出码 0
7. 知会 I 类：结果送达被知会方——检查点：送达名单勾完

## 已知局限

- RACI 是口径对齐工具不是权力工具：组织真没有决策文化时，RACI 表会变成墙纸——A 角色的实际拍板意愿是前提
- 升级路径依赖组织架构清晰：矩阵型/汇报线模糊的组织里"直属上级"可能是复数，先按本组织实际汇报线改口径再用
- 确认清单加长会拖慢决策：确认范围按"影响面"圈定，不全员抄送
- 跨部门确认不改变可逆性判断：B类未必都不可逆，A类也未必可逆——确认机制与可逆性分级是两个独立维度，别混用
- 无对照实验级效果证据；采纳理由是留痕与责任清晰，不是"协同必然更顺"
