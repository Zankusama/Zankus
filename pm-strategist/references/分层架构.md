# pm-strategist 分层架构说明（参赛评审可直接引用）

> 目的：把 v5.0 的"七态状态机 + 脚本化闸门 + 唯一状态载体"讲成一张可给审查者读的地图。
> 定位：设计文档，**不是使用说明**。使用者只需跟 SKILL.md「执行流程」走；本文件回答"它到底怎么分层、每层管什么、数据怎么流"。

## 0. 一句话架构

**决策脚本化 = 识别层出语义 → 闸门层确定性拦截 → 状态层管进度 → 呈现层给用户 → 存储层落盘为一棵可回看的树**。
判定落到 AI（语义），强制落到脚本（确定性），透明落到闸口 A 透出（用户监督）。脚本不伪装成"脚本在替你做判断"。

## 1. 五层职责

| 层 | 职责 | 载体 | 关键机制 |
|---|---|---|---|
| **识别层** | 把任意一句产品问题抽成"动作 × 对象"两个原语 | AI 语义判断 | 25 格矩阵路由（scene-router.py 校验合法性）；旧词法匹配退役 |
| **闸门层** | 对流程做确定性拦截 | 一次性脚本（见 §2） | 退出码 0/1/2；fail-closed（缺状态=当作失败，不静默放行） |
| **状态层** | 管"流程走到哪一步"，是唯一进度事实源 | config/session_state.json | state-gate.py 七态状态机 + 门禁 + 幂等回写 |
| **呈现层** | 给用户看什么、不给用户看什么 | check_output.py 台面校验 | 台面四区契约（【建议】/【为什么】/【为什么不选别的】/【换挡条件】）；T1-T11 断言组 |
| **存储层** | 决策收敛后的唯一资产形态 | decision-record.py | 自包含 HTML 决策档案（9 字段+探讨轨迹+归位），收敛闸三层断言 |

> 呈现层的核心纪律：**框架名与机制黑话不上台面，论证必须上台面**。用户看到的是人话结论+依据+反方+掉头信号，看不到"路径声明/主查 ref"这类内部调度词。

## 3. 七态状态机（唯一合法进度路径）

```
S0_IDLE →① S1_ROUTED →② S2_PROFILE_OK →③ S3_INFO_GATHERING →④G闸 S4_DRAFT
        →⑤ S5_DEBATING ⇄ S6_CONVERGED →⑥ S7_ARCHIVED
  特例：S5→S4（critical 中途补齐 → 强制回 S4 重出初步版，不许带旧结论走）
  特例：S4→S6（用户显式跳过探讨，须存原话证据）
```

六门转移条件：① routing.action/object 合法 ② routing.confirmed_by_user 非空（分歧已仲裁）③ profile_ok=true ④ G 闸 critical 全已确认 ⑤ 初步版过 check_output（S4→S6 直跳须跳过声明原话）⑥ 收敛证据 + dr_id 非空。
缺状态 / schema 版本落后 → **fail-closed 拒读**（宁可拦住也不静默放行）。设计取舍见 SKILL.md「会话状态管理」节。

## 4. 数据流（一次完整决策的骨架）

1. 用户一句话 → 识别层抽「动作×对象」（AI 语义）→ scene-router 校验合法性 + 查矩阵 → **闸口 A 透出确认**（分歧须双候选呈现给用户选）。
2. 过门①→②（用户确认原话存入 routing.confirmed_by_user）→ 身份层 profile-check 回显核对（过门③）。
3. S3_INFO_GATHERING：info-gate 台账记账 + critical 清单预置；补问到关键项 → 过门④（G 闸）。
4. S4_DRAFT：AI 出台面初步版 → check_output 校验四区（缺键/黑话/裸百分比被拦）。
5. S5_DEBATING：用户反驳循环（增量更新，无新意熔断）→ 收敛证据（用户原话）→ S6_CONVERGED（过门⑤）。
6. decision-record.py 落盘：三层收敛闸（原话引用/跳过声明证据/state 须 S6）→ 自包含 HTML → 台面档案提示行收尾 → 回填 dr_id → S7_ARCHIVED（过门⑥）。

```
用户 → 识别层 → [闸口A·scene-router] → 状态层[state-gate]
   → [闸口G·info-gate] → [闸口C·profile-check]
   → 台面[check_output] → 探讨循环 → [闸口B·decision-record] → 存储层[HTML档案]
```

## 5. 设计取舍（诚实声明，勿外推安全承诺）

- **核心判定为何归 AI**：25 格矩阵的格子是有限的，但用户的表达是无限的。词法匹配只能接住"规范说法"，接不住半成形与反语。故语义抽取交给 AI，脚本只做**确定性能做的**（校验合法性 + 查表 + 断质量下限）——用透明换可监督，脚本不伪装成"脚本判定"。
- **状态层为何用文件而非事件**：单机终端会话，无后台事件总线；一个 JSON + 退出码是零依赖、可 grep 审计的最小事实源。
- **已知局限（如实）**：状态脚本能**校验**状态，但不能**强制** AI 去写状态。缓解=把"更新 state"写进每个 phase 的进入动作 + 缺 state 直接 fail-closed（不更新就走不动）。这不是物理 hook，是等价确定性（非零退出即停）。
- **质量下限 ≠ 判断力**：所有闸门只保证下限（选项摆齐/反方可证伪/风险不空转/依据有出处）；"选哪个"的判断胜负手仍在用户。不夸大。
