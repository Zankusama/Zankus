# ref-01 新品立项与产品定义（场景S1·A类）

> 场景：新品该不该立项/机会值不值得投/新品概念怎么定义。A类=PM职责内完整决策，建议做到分析透。
> 结构：一、检查单（五闸通用版）→ 二、互补框架要点（7个，标来源与互补闸位）→ 三、输出模板。
> 通用版声明：不绑定特定组织术语；APQP（先期产品质量策划）仅作"前端策划、分阶段锁定"思路参考，不做主框架。

## 一、检查单 · 五闸开发流程通用版

> 用法：按闸逐项勾选。**核心项=PM必做**，缺任一项=闸不过；**协作项=PM提供输入**，由职能方确认。闸口决策四分类=**通过/否决/搁置/重做**（判据见闸后说明）。

### 闸1 机会输入
- [ ] 【核心】市场规模与增速有数据来源（行业报告/平台数据/一手调研，注明出处）
- [ ] 【核心】目标人群画像初版（谁买/谁用/购买动机）
- [ ] 【核心】竞争格局扫描（直接竞品≥3+替代品，各一句定位）
- [ ] 【核心】渠道需求输入已收集（渠道要什么货/什么价/什么毛利）
- [ ] 【协作】公司战略方向匹配度（战略层输入，管理层确认）
- [ ] 【协作】用户需求原始素材（访谈/评论/客服记录）已归档

### 闸2 商业论证
- [ ] 【核心】成本预算框架（研发/生产/营销三类，示例占位：量级区间而非精确数）
- [ ] 【核心】毛利测算初版（目标毛利结构与价格带假设）
- [ ] 【核心】回本周期估算（含假设条件清单）
- [ ] 【核心】战略一致性一句话（这个品服务哪层战略）
- [ ] 【协作】财务口径校准（财务提供标准测算模板）
- [ ] 【协作】产能/供应链可行性初判（供应链方输入）

### 闸3 概念定义
- [ ] 【核心】产品概念一句话通过测试（谁/什么场景/什么问题/凭什么买你）
- [ ] 【核心】核心利益点与支撑点对应表（宣称什么/凭什么信）
- [ ] 【核心】差异化声明（对比竞品的差异点，可验证）
- [ ] 【核心】价格带定位（落在哪个价格带、为什么）
- [ ] 【协作】概念测试报告（定性/定量结果，调研方执行）
- [ ] 【协作】法规宣称边界初核（哪些说法能说，法务/合规输入）

### 闸4 开发验证
- [ ] 【核心】概念验证结论（目标用户买不买账，样本与结论注明）
- [ ] 【核心】试制品/原型验证（功效/体验达设计要求，验证方法写明）
- [ ] 【核心】成本达成核对（量产目标成本 vs 实际试制成本）
- [ ] 【核心】宣称合规复核（终版宣称与法规边界一致）
- [ ] 【协作】包装与视觉方案（设计方产出，PM确认符合概念）
- [ ] 【协作】批量生产可行性（工艺/良率/交期，制造方输入）

### 闸5 上市复盘
- [ ] 【核心】上市准备清单齐（渠道/物料/价格/节奏四要素）
- [ ] 【核心】渠道铺货计划确认（首铺渠道与铺货率目标）
- [ ] 【核心】复盘机制已定（复盘日期+假设清单回看点）
- [ ] 【核心】市场反馈回路（数据看板/周报口径定义）
- [ ] 【协作】上市培训与话术（销售/市场执行）
- [ ] 【协作】信息反馈链（销售数据/用户评价回流路径）

### 闸口决策四分类（每个闸口结束时的出口动作）
| 分类 | 判据 |
|---|---|
| 通过 | 核心项全过、协作项有明确输入、无未缓解的高风险 |
| 否决 | 战略不符或商业论证不成立，且无低成本修正路径 |
| 搁置 | 方向成立但关键输入缺（数据/产能/合规），限期补齐再议 |
| 重做 | 概念或验证结论被推翻，需回到上一闸重新定义 |

## 二、互补框架要点（7个，每个标来源+互补闸位）

> 用法：主流程=五闸；互补框架按需单点引入（每条建议引用1-2个对题框架，不堆砌）。要点为提炼转述，以原体系为准。

1. **NPD 新产品开发流程**（来源：PDMA NPDP 知识体系）——互补全部闸位。把新品从机会识别到上市分成标准阶段，与五闸对位使用；要点：产品创新章程（PIC）先立、阶段评审后行。
2. **精益创业 BML+MVP**（来源：Eric Ries《精益创业》）——互补闸3-4。用最小可行产品（MVP）快速验证"构建-衡量-学习"循环；要点：先验证最致命的假设，再投入完整开发；适用于概念不确定时的低成本试错。
3. **设计思维**（来源：IDEO/斯坦福 D.School 五阶段：共情-定义-构思-原型-测试）——互补闸1、3。从用户场景出发重构问题定义；要点：先共情（用户怎么用、怎么抱怨）再定概念，避免"工程师视角自嗨"。
4. **模糊前端 FFE**（来源：产品创新管理研究（Koen 等新概念开发模型））——互补闸1。机会识别到概念定型之间的"模糊地带"用机会识别/机会分析/构想生成三步管；要点：前端越省事，后端越返工。
5. **PIC 产品创新章程**（来源：PDMA NPDP）——互补闸2。一页纸说清：目标市场、业务目标、技术边界、资源约束；要点：章程是商业论证的浓缩版，写不出章程=论证没想清。
6. **KANO 模型**（来源：东京理工大学 狩野纪昭）——互补闸3。区分基本/期望/兴奋需求，定核心利益点与差异点的主次；要点：基本需求不做=出局，兴奋需求才构成差异；配套脚本 `scripts/kano-classify.py`。
7. **门径-敏捷混合**（来源：Cooper Stage-Gate × 敏捷开发实践）——互补闸4。结构闸门管"做不做"，敏捷冲刺管"怎么做"；要点：闸间用短迭代产出可验证物（试制品/概念测试），闸口只看验证结果不看 PPT 承诺。

**APQP 思路参考**（仅参考不套用）：先期策划、分阶段锁定要素、跨职能同步评审——取"越早锁定关键要素、返工越少"的思想即可，其汽车行业表单体系不迁移。

## 三、输出模板

### S1 决策建议模板（建议6要素）
```
【场景】S1 新品立项与产品定义 ｜ 可逆性=🟢/🔴/🟡[|⚠️高风险] ｜ 主查=ref-01+fm-01
1. 选项（≥2，含不做/维持现状）：立项并按五闸推进 / 不做（维持现状）/ [示例占位：授权小步试错（MVP先行）]
2. 推荐倾向：明确倾向哪个选项，一句话理由
3. 权衡分析：各选项 收益/代价/前置条件 对账
4. 不做项说明：放弃"不做"之外的哪些路（如：不做全渠道同步铺开）
5. 风险（6维度命中项）：法规/市场/竞争/供应链/财务/组织——只列风险点+怎么验证
6. 数据需求引导：补齐哪些数据可把"草案"变"已定"（市场规模口径/成本精确数/概念测试样本）
```

### S1 决策记录模板（DR9字段，收敛终端）
```
# DR-YYYYMMDD-<slug>
- 问题：[示例占位：A品类是否立项新品X]（场景S1｜决策者=用户｜截止=YYYY-MM-DD）
- 选项：立项 / 不做 / 小步试错（含不做/维持现状）
- 决定：用户已拍板=决定原文；未拍板=推荐倾向
- 依据：ref-01五闸核心项通过情况+互补框架哪条（标注文件与条目）
- 反方意见：最强反方+什么数据/条件会推翻本决定
- 风险：6维度命中的风险点+验证方式（不替用户做风险结论）
- 假设清单：每条 ⚠️ 前缀"假设·待验证"
- 复盘日期：YYYY-MM-DD（建议=过闸5后的合理观察期末）
- 状态：草案/已定/复盘/关闭
```

---
适用时机：闸1-5贯穿使用；轻决策（可逆）可只跑闸1-2核心项速断。已知局限：五闸是线性骨架，市场剧变时应回闸重跑而非硬推；检查单保证完整性，不保证正确性。
