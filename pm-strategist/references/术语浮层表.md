# 术语浮层表（B-lite · 快消术语唯一口径）

> **用法**：识别到用户对术语不熟 → 用一句人话先解释（下方"白话"列），不打断决策主流程；详细口径与取数提示以本表为准。
> **边界（防漂移）**：生词 ≠ 路由失败——原语缺失/对象枚举外 → 走四态澄清/跨域拆解出口，**禁止以记词条代替问意图**。
> **收录纪律**：A 类（科普）= 作者预置行业词典，静态交付随包分发、接收者零维护；长尾仅当真实对话中用户显式表现出不懂且该词在决策路径上真实出现才新增，禁止 AI 预判式预填。
> 本表=纯公共知识、零私人信息，兼作取数地图口径源（ref-06 组件②）。
> **口径纪律**：全包术语口径以本表为唯一准；SKILL.md/references 出现同名词汇时按本表解释。

| 术语 | 一句白话 | 标准口径 | 取数提示 |
|---|---|---|---|
| 动销率 | 摆上货架的货里，真正在卖动的比例 | 动销 SKU 数 ÷ 在库 SKU 数（统计期内有销量即算动销） | 同店口径；周粒度最灵敏 |
| 铺货率 | 目标门店里，实际摆了你货的比例 | 有货门店数 ÷ 目标门店数 | 区分"进货"与"上架"：经销商进货≠终端铺货 |
| 费比 | 花出去的费用占销售额的比例 | （促销费用+渠道费用）÷ 销售额 | 与毛利红线联动看；分渠道拆开算 |
| 价盘 | 同一产品在各渠道的成交价体系 | 各渠道实际成交价格带及其梯度关系 | 成交价≠牌价；促销常态价单列；价盘乱=渠道利润体系失控起点 |
| 窜货 | 货流向了非约定的区域/渠道 | 跨区/跨渠道低价流货（通常因价差+返利钩子） | 治理靠价差设计+编码追溯+返利挂钩，不是靠口号；见 ref-05 价盘一致性 |
| 临期 | 保质期剩余时间逼近警戒线的库存 | 按品类行业标准（常见为剩余 1/3 保质期）触发临期处理 | 临期处理动作（折价/渠道分流）进约束卡，别拖到过期 |
| 安全库存 | 防断货而常备的缓冲库存 | （最大日销量×最大补货周期）−（平均日销量×平均补货周期） | 旺季前重算；单点依赖供应链=黄灯 |
| 周转天数 | 库存多久周转一圈 | 平均库存 ÷ 日均销量（天） | 越短越健康；突变常先于动销恶化出现 |
| 毛利（真实毛利） | 卖一箱真正落袋的利润，不是"牌价减成本"那么天真 | 真实毛利 = 净价（牌价 − 渠道费用 − 返利）− 成本；只看牌价算 = 虚高口径（系统性高估 15-25%） | 算账一律走 calc-pricing.py 净价层（闸口 H 强制）；"毛利红线"与费比联动看 |
| 返利 | 卖够约定量/条件后，渠道商能拿回的返钱 | 净价 = 牌价 − 渠道费用 − 返利；返利基数（进货额 or 销售额）与周期（月/季/年返）必须先问清 | 返利是窜货与价盘乱象的常见钩子（ref-05）；算账时是扣减项不是成本项 |
| 渗透（低价渗透） | 用低价先把市场份额抢下来，利润先让路 | 定价目标四选一（利润优先/份额优先/渗透优先/形象锚定），渗透优先=以量换份额 | 本包"渗透"=定价策略，勿与"铺货渗透"混；竞品跟价则渗透失效（反方意见高频素材） |
| 试销 | 先小范围卖卖看，验证过了再放量 | 五闸开发闸 4 核心：范围/指标/判停线（多少算成、多少判停）写进计划 | 试销≠铺货；判停线没写=没计划（stage-gate-check.py 会查） |
| 断货 | 货卖完了、补不上来 | 断货率 = 断货 SKU×断货天数 ÷（总 SKU×营业天数）；与安全库存镜像 | 断货损失（丢单+伤陈列位）vs 库存成本是权衡；突变先查供应链单点依赖 |
| 进场费 | 进大渠道（商超/KA）先交的"门票" | 一次性渠道门槛费用，属渠道费用组成（区别于持续扣点） | 砍 SKU 前先查渠道合约是否含条码数门槛——砍了可能丢进场资格（反方意见典型素材） |
| 贡献度（单品贡献度） | 这个单品到底给公司赚多少、占多大份 | 每 SKU 账本：销售额/毛利额/占比（ref-02）；砍品看贡献度不看销量排名 | 贡献度数据滞后市场变化——"该砍的品恰在拐点前"是最常见误判，淘汰动作给缓冲期 |
| 决策情境 | 这次决策自带的背景，用完就扔 | 决策目标 / 预算约束 / 时间窗 / 数据缺口 四变量；不落盘，随 DR 草案承载，决策关闭即过期 | 当次问、当次用；不写入 profile（升级通道除外） |
| 披露分层 | 该问多细，看这决策退不退得回 | 披露深度 = 可逆性 × 影响度：🔴不可逆缺关键项停住；🟢可逆只问命中变量（≤2）；快轨走低档豁免 | 同一决策线 DR 草案在案 → 从假设清单读回，不重问 |
| 回显确认 | 写进记忆前，先把将写入的话复述给你听 | [stated] 只存亲口确认的：回显整份 profile → 逐条确认/纠正 → 才打戳落盘 | 首采/大改/升级 → 全量回显；90 天重验只回显变更字段 |
| 升级通道 | 同一件事好几次都这么定，就问要不要记进公司长期档案 | 跨 ≥2 次决策仍成立 → AI 白话问"要不要记进你的公司长期档案？"→ 回显 → 判据归位 | 只在情境中自然触发，不主动挖 |
| 记忆判据 | 什么记一辈子、什么用完就扔，就两问 | 问①"换客户/渠道/档期还一样吗"（变=短期）；问②"不换公司不换赛道会一直稳定吗"（会=长期） | 拿不准按短期；宁可不固化，不存过期信息 |
| 同词异层 | 同一个词，问数字和问底线是两个意思 | "这批报多少"=短期问法；"价格底线？绝不打 9.9？"=原则问法 → 长期（定位禁区） | 数字/原则分不清 → 问用户一句，不自己猜 |
| 身份层（决策前提库） | 三层引导第一层：先固化"你是谁/在什么处境"，决策才谈得上校准 | 决策前提库 = L0 基座（行业/品类/目标客群/公司规模）+ L1 结构（品牌阶段/渠道结构/拍板权/定位禁区），无 L2 | 旧称「行业适配/行业适配层」已并轨（组件④ 标题+枚举+测试），禁止再用旧称——再出现即术语第三次漂移 |
| SKU | 一个单独的货品编号——同品不同规格/口味/包装各算一个 | Stock Keeping Unit，最小存货单位；组合管理、贡献度、砍品都以 SKU 为粒度 | "SKU 数"与"单品数"勿混：一支产品 3 个规格=3 个 SKU |
| KA | 大卖场/连锁商超这类重点大客户渠道 | Key Account；特点是门槛费用高、账期长、要求条码与促销配合 | 进场费/条码费/堆头费集中在 KA；砍 SKU 前先查 KA 合约条码门槛（见「进场费」条） |
| 一批/二批 | 经销商层级——一批从厂家拿货，二批从一批拿货 | 一级/二级经销商；层级越多每层加价越多，价盘越难管 | 窜货常沿层级价差发生；算渠道毛利按层级逐层扣 |
| SKU 深度/宽度 | 深度=同一品出多少变体；宽度=覆盖多少品类 | 深度=单品类内 SKU 数（口味/规格/包装）；宽度=品类跨距 | 组合诊断先分清问题在深还是宽：深了自我蚕食，宽了资源摊薄（ref-02） |
| CP/TP | 对消费者让利 vs 对渠道让利 | CP=消费者促销（买赠/折扣）；TP=渠道促销（进货搭赠/返利） | 费比口径里两者常被混记——拆开看才知道让利于谁（ref-04 促销费效） |
| 大盘 | 整个品类的总盘子 | 品类总体量与增速，"跑赢大盘"=增速快于品类均值 | 换挡条件里"低于品类均值"的比较基准=大盘口径；口径不同结论会反转 |
| 动作原语（增/删/改/择/判） | 你真正要做的是哪一类：新做 / 砍掉 / 改动 / 在几个方案里挑一个 / 先评估现状再定 | 五原语=产品决策路由的最小动作集：增=引入原本没有的；删=移除已存在的；改=原地变更不增减；择=在已摆上桌的选项间 A/B 取舍；判=只出评估结论不改变任何东西 | 机械原语名只进 AI 内部记录，**问用户时必须翻成人话**（"在几个方案里挑一个"/"先评估现状再定"）；用户答案构成 动作×对象 即归位（ref-06 路由澄清白话问法） |

> **消歧注**：**拍板权** = 终审权（谁最终拍板，身份层 L1 字段，组织变动才变）；**"谁拍板"**（B 类约束七维）= 流程参与方（定价要过财务/销售/渠道哪些部门）。两者勿混。

## 补问格式模板（单问信息量；随 R-3 澄清轮断言生效）

> 背景：补问 ≤2 只约束"问几条"，未约束"一问塞多少"——一问内嵌 9 个子项（"①…⑨…"排比）等于把问卷倒在用户脸上，机器按子项数计问（check_output.py R-3 嵌套子项计数），一处违规全轮 FAIL。
> 用法：补问时每问 = **一个疑问句 + 选项/格式示例**——给格式比给解释省用户的时间；用户照格式回一个词也行。

| 场景 | ❌ 一问塞多子项（R-3 会拦） | ✅ 单问+格式示例 |
|---|---|---|
| 渠道构成 | "渠道构成怎么样？线上占比多少？线下几条线？经销商几层？各占多少？" | "各渠道大概占几成？格式：线上 X 成 / KA X 成 / 经销 X 成（估的就行）" |
| 价格带 | "竞品卖多少？哪个价格带？我们卡哪里？弹性大不大？" | "对手常态成交价大概什么档？格式：竞品 X 元档（如 19.9 / 29.9 两档）" |
| 复购 | "复购怎么样？几个月？比例多少？和大盘比呢？" | "复购有数吗？格式：X 个月内复购约 X 成（没数就说'没数'，我按假设挂账）" |

- 纪律：每问一个疑问句；子项 ≤2 个才可并列（格式示例里的"/"不算子项）；格式给到"用户回一个词/一行就能填"的粒度。
- 没数的信息 → 显式假设挂账（⚠️ 假设·待验证 + T11 自曝尾巴计数），不逼问、不连环追问。
