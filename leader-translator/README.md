# leader-translator · 领导翻译官（使用说明 / 分发版）

一句话：**围绕目标找对事，再让 AI 把事做对**——你出想法，skill 帮你把需求问清楚，产出 AI 能直接执行的任务书。（原名 leader）

## 安装

1. 把整个文件夹放进你的 agent 客户端的 skills 目录（如 `~/.workbuddy/skills/leader-translator/`）
2. 重启客户端，让 skill 被加载
3. 直接用人话描述你的想法，skill 会自动接住

## 什么时候会触发

- 「需求说不清」「想法模糊」「帮我理理」→ 会触发
- 「让 AI 干活但反复返工」「结果不满意」→ 会触发（用同一套澄清帮你把"不对"讲明白）
- 「写个任务书/goal」「把活拆给 agent」→ 会触发
- 一句话能说清目标+约束+验收的需求 → 会触发，但直接给简化任务书，不走全流程（不折腾你）

## 你会经历什么（7 步，每步有闸门）

1. **理清目标**——判断目标形态：产品/工具/内容/流程类先走五层面定义（给谁用→解决什么→什么形态→什么画面→不要什么），模糊的先出方向让你选。**闸门：五层面答案过脚本校验**
2. **调研**——AI 自己能查的自己查，不烦你；领导有知识库就说一声，会先挖你的「第二大脑」。**闸门：查不到的必须标「假设，未验证」**
3. **盲点扫描**——AI 用已知补你没想到的，给你看「补盲清单」（哪些要你拍板、哪些它猜）。**闸门：必须有 💡 主动补盲项**
4. **提问，每轮 ≤5 个、带选项和推荐**——不想想就说"都按推荐的来"；每轮结束复述确认。**闸门：⚠️ 项清零 + 小结存在**
5. **写书**——先给你看任务书骨架（金字塔结构），**任务书够大（≥3 任务 或 ≥2000 字符）时还会先画一张金字塔图**，你点头才写正文。**闸门：你人工点头**；写完机器核对覆盖清单防漏
6. **交付**——你粘给执行 agent 跑
7. **验收**——跑完 AI 验收，给你 5 行内的人话报告

## 自带脚本

| 脚本 | 用途 |
|---|---|
| `scripts/stage-gate.sh` | **六道闸门 G1-G6**（每步产出物校验，防跳步）：G1-G4 自检（目标清晰/调研完成/补盲到位/提问穷尽），G5 写书前人工核对清单，G6 写书后自动检查（goal-lint+回归目标+重点复核清单） |
| `scripts/goal-lint.sh` | 任务书发出前自检（字数/六节/黑名单词/产物路径合规/拆书方案完整/可执行判定），`--self` 可体检 skill 本体 |
| `scripts/guard.sh` | 判卷冻结（snapshot/verify）+ 基线守线（record/check），防执行者作弊 |
| `scripts/coverage-check.sh` | 完整性核验（对照覆盖清单逐点检查任务书），防管理者偷删内容 |
| `scripts/pyramid-gen.py` | **金字塔结构图生成器**（路径预览用）：`--apex 塔尖 --pillars 柱1,柱2 --base 护栏1,护栏2`，参数化自适应，零依赖 |

## 升级 / 回滚

- 改 SKILL.md 前先备份一份，version 升号（v4.x.x → v5.x.x 是大版本，跨版本要重审）
- 改完跑 `scripts/goal-lint.sh --self SKILL.md` 体检，全 ✅ 才算改好
- 想回滚就换回备份文件

## 兼容性

完整功能（斜杠命令、任务书直粘）需要支持 skill 加载的 agent 客户端；没有的客户端，把任务书代码块直接粘贴发送即可用。
