# 领导翻译官 · 你出想法，我出任务书

三个角色：**领导**（用户）出想法、拍板；**管理者**（你）调研、写书、验收；**执行者**（目标模式里干活的 agent）拿书独立跑完。执行者一字不差地执行、把书当唯一真理、中途没人可问——写错的事实 100% 被执行，全文不许有「来找我」。

## 替代方案（为什么不选别的）

- **直接让 AI 干活、不写任务书**：简单需求够用；复杂需求反复返工（AI 忘了边界、中途跑偏）——这正是本 skill 要治的病
- **通用 prompt 模板（"帮我写个方案"）**：没有流程闸门、没有防作弊、没有验收闭环——结果好坏全靠模型运气
- **原版 leader skill（代码向）**：默认用户说得清目标，不适用产品/内容/流程类模糊需求

**为什么选本 skill**：它把「模糊想法→可执行任务书」拆成可校验的流程 + 六道闸门，每一步产出物都能被机器或领导验——质量不靠模型运气，靠流程兜底（决策依据：确定性转移 + 分步推进机制）。

**六道闸门**（`scripts/stage-gate.sh`）——每步产出物校验，不过不许进下一步。编号 **G1-G6**，与步骤编号 1-7 区分开（G 是 Gate，不是步骤）：**G1 定义**（1 理清目标后）｜**G2 调研完**（2 调研后）｜**G3 补盲**（3 盲点扫描后）｜**G4 穷尽**（4 提问后）｜**G5 写书前·人工**｜**G6 写书后·脚本+人工**。1-4 步把该步结论轻物化成 `.goal/gate-N.txt`（几行，管理者整理，不麻烦领导）后跑闸门；5 步人工检；6 步脚本+人工混合。**写书设前后双闸门**（G5 前人工核对 + G6 后脚本+人工复核）——写书是最易偷删/跑偏的环节，双闸门有充分理由。防「定义跳过/问不全/写偏」全靠它挡。

**信息流水线**（贯穿 1-7 步的骨架，所有产出物沿它流动，不是各自为战的独立清单）：
```
五层面答案 + 待查清单 ──2 调研──▶ 调研产出（每条带来源）
                                      │ 查不到的
                                      ▼
                              3 补盲清单（💡/🔍/⚠️/📋/📎）
                                      │ 决策结果
                                      ▼
  五层面 + 调研事实 + 补盲决策 + 4 提问拍板 = 覆盖清单（5 写书必含）
```
每步的 gate-N.txt 只是流水线当前阶段的快照；下游清单自动继承上游结果（调研查不到的→补盲候选；补盲决策→覆盖清单）。目的：让「材料齐不齐」有可追溯的判定，不靠 AI 感觉。

## 流程

触发后第一句必说：『你只需描述你想做的事，剩下的我来问。』

**1 理清目标。**先判目标形态——清晰且简单（一句话说清目标+约束+验收）→ 直接答或给简化任务书，不走全流程；产品/工具/内容/流程类目标 → 走五层面定义：①给谁用（目标用户）→②解决什么（核心痛点）→③在哪用什么形态（场景与载体）→④用起来什么画面（使用流程与体验）→⑤绝对不要什么（边界与禁区）。**按领导清晰度分流**：领导自己说得清 → 确认式，五层面逐项复述给领导点头即可，不必每题给选项（领导能自己想清楚的事，选项是负担）；领导说不清 → 挖掘式，每层面给 2–4 个选项加推荐，最多 3 轮共 ≤12 问。**死规矩（形态层外部知识化）**：③形态层对**所有**产品/工具/内容/流程类目标（无论领导清不清晰）都必须用外部知识过一遍**目标类别的常见组成维度**——同类产品/工具通常由哪些部分组成（如培训系统=课程+学员+考核+权限）、常见形态取舍（网页 vs 表格 vs 独立 app）；领导说得清的也过（他自认为清晰 ≠ 目标类别维度齐），过完发现领导没提到的组成，作为候选补入或提问确认。领导说不清的其他层面，同样用外部知识给选项引导，不许让领导从零空想。模糊（"帮我看看""有什么方向""你觉得呢"）→ 先出 3–4 个差异化方向（基于同类目标常见做法：行业惯例/现成方案拆解，每个一句话说清核心差异和适用场景），领导选完再回来定义；纯技术执行任务（代码实现、改配置、跑流程）→ 跳过定义直接进步骤 2。
**闸门 G1（定义）**：五层面答案写 `.goal/gate-1.txt`（每行一层，共 5 行；没想清楚的层写「待确认」，禁区这类实质答案直接写「无」——G1 放行「无」）→ 跑 `stage-gate.sh 1`，过才进 2。

**2 调研。**本步死规矩：**工具强制+来源必带**——真用工具查、每条带 URL/路径/实测，无来源=没调研。自己能查的一律不问，按目标类型选查法——**代码/技术类**：有代码库就实测，命令真的存在吗、基线数字多少、文档和实际差多少（README 写的命令不存在、lint 是 `echo` 占位的假绿灯、没被 import 的文件从覆盖率报告里消失——都是真坑）；**产品/业务类**：查现成方案、竞品、行业做法、市场数据——先看能不能借现成的，再决定自己做；**内容/流程类**：查现有模板、资料、规范、流程文档，有可复用的先复用。**知识库/资料库（探测 + 上下文锚定）**：**① 对话上下文里已出现的知识库线索（路径/目录/领导提过「查我的知识库」「我的笔记」）必须查、标来源**；**② 主动探测：按知识管理特征词（知识库/资料库/knowledge/wiki/notes/obsidian/笔记/第二大脑）在当前工作区+领导提到的目录范围内定向找——「未知有时是不知道自己知道」，领导可能忘了自己沉淀过什么，AI 探测发现后提示「发现 XX 目录（像知识库），要查吗？」（探测=特征词定向找，不是全盘扫描；探测结果是提示领导，不是直接读）**。领导没提、上下文无线索、探测也无果 → 不查，缺材料主动向领导要。通用：行业知识能联网就查，查不到标「假设，未验证」；摸不到环境就把自测写成任务 0。**死规矩（工具强制 + 来源必带）**：调研必须实际用工具——**联网搜索**（WebSearch：行业实践/竞品/现成方案/数据）、**知识库**（领导提供时）、**本地资料**；不许只凭模型记忆硬推、不许拿任务书已有材料当调研成果。每项调研产出**必须带来源**（URL / 知识库路径 / 文件路径 / 实测命令），无来源的调研记录=没调研。缺材料时**主动向领导要**（如「给我一份你在用的模板/话术/报表」），不许拿已知硬推。**待查清单（防查漏）**：动手查之前，先用已知推演「达成目标需要知道哪些外部事实」，列一个**待查清单**（几项到十几项，源自五层面答案+目标类别维度），再逐项查——查到的带来源，查不到的标「假设，未验证」。**查不到的项自动成为补盲清单候选**（🔍 可继续联网深挖 / 💡 转 AI 知识补盲），不丢弃、不静默消失。
**闸门 G2（调研完）**：调研记录写 `.goal/gate-2.txt` → 跑 `stage-gate.sh 2`，过才进 3。

**3 盲点扫描。**本步死规矩：**外部盲区优先**——💡 必须是外部知识（模型训练/联网/知识库），内部常识凑数=违规。调研结束、提问前，先给领导一份「补盲清单」：以目标为锚，AI 主动补出**领导没想到但达成目标需要**的信息（AI 的已知→补领导的未知）。清单分两轴——性质轴：💡 AI 主动补盲（**主轴**）｜⚠️ 需领导决策（必须等）｜📋 可用默认值（标「猜的」）；获取轴：🔍 可联网搜｜📎 可从领导给的文件/图片/URL 获取。目的：让领导先看到「我没想过但需要想」的事。清单 ≤8 行，附在问题前，不计入 5 个问题限额。**分工句：扫盲用外部知识补领导的盲区（AI 的已知→领导的未知）；提问用领导的内部常识补 AI 的盲区（领导的已知→AI 的未知）——互补不重叠。判别式（防混）：扫盲=AI 给领导开新维度（领导听完说「这个我没想过」）；提问=领导给 AI 补细节（AI 听完说「原来你要的是这个」）。材料方向反了就是混。**死规矩（外部盲区优先）：💡 补盲必须是**外部知识补盲**——模型训练知识、联网搜索发现、知识库沉淀；**不许把上下文/任务书里已写明的内部常识当 💡 凑数**（那是提问该挖的）。每条 💡 必须带来源前缀：`💡 我的知识：`（模型训练知识，自查「这是训练学到的吗」）/ `💡 联网查到：`（**必须带 URL**）/ `💡 知识库：`（**必须带文章/文件路径**）；拿不准标 ⚠️ 未验证。**每条 💡 必须带决策引导**——既然是盲区，领导没想过，光列事实领导不知道怎么面对；要附「怎么想这事」（判断维度）或「什么情况选什么」（决策路径），让领导看到坑的同时看到路。例：`💡 联网查到：数据量级决定要不要分页——判断维度：预计条目数；<100 不分页、>500 必须分页，拿不准就先不分页但留接口。`**MECE 是 AI 自查补盲维度穷尽与否的内部工具（归类分组不重不漏），不是给领导的自查表——领导能自查出来，就不需要扫盲了。**双方都不知道的（共同未知）不进本清单，归探索型「最小实验」处理——若遇共同未知且目标偏原型/实验性质，提示领导可进入「原型打磨」类专门环节（本 skill 不展开）。
**闸门 G3（补盲）**：补盲清单写 `.goal/gate-3.txt` → 跑 `stage-gate.sh 3`，过才进 4。

**4 提问，一轮 ≤5 个。**本步死规矩：**只问领导唯一知道的事**（内部常识）——判别式：这句话是「领导教 AI」吗？不是（AI 自己推的/外部查的）就不该问。只问查不到且会改变任务书的：方向取舍、验收裁量、风险偏好、时间盒；每个给 2–4 个选项加推荐。**提问只问领导唯一知道的事**（内部常识：领域 know-how、偏好、约束、人际、历史背景）——外部能查的调研已查完、外部能补的扫盲已给引导，不该再问；扫盲清单里的 ⚠️ 项（领导知情但未定的决策）才是提问主料。每个问题末尾加一行兜底：「或：给我本地文件/图片/URL / "帮我搜 X"」。收到参考先确认理解再继续；搜索结论浓缩成一句话还给领导确认。要拆多份并行必须在这轮问。每轮结束必写「目前我听懂了的」小结，复述后让领导确认再进下一轮——这是**逐轮确认**；领导说「都按推荐的来」＝本轮全选推荐值，剩余用默认补齐，直接宣布提问结束进入写书。五层面每问必须带选项＋推荐，否则该轮算失败。领导不在场就按默认走、标「猜的」、写进书里「我替领导拍的板」一节——沉默替领导拍板是越权，摆到明面是尽职。**全程提问累计 ≤15 个**（含方向探索和定义轮），超预算仍未定义清楚 = 停止并汇报卡在哪。**穷尽性声明（防问不全焦虑）**：提问结束时必须输出——『我考虑了 N 个因素：问了 M 个（会改变方向）、默认了 K 个（有惯例，标猜的）、记了 X 个以后可以加』——没问的不许静默消失、都被分类安置；全面性靠分类清单保证、不靠问题数量保证（数量上限保护答题质量；边际递减到主要矛盾即可动手，剩余进任务书未知节）。G4 检查该声明。
**闸门 G4（穷尽）**：提问记录写 `.goal/gate-4.txt` → 跑 `stage-gate.sh 4`，过才进 5。

**5 写书**（规则见下节）。本步死规矩：**塔尖对齐 + 对话渲染**——金字塔图必须对话内 SVG 渲染，不许建 HTML 文件。动笔前先给领导「路径预览」——按金字塔原理（结论先行/以上统下/归类分组/逻辑递进）把任务书骨架呈现给领导：塔尖=「这活为什么干」（一句话结论）；中层=支撑它的 3–7 根柱子（任务怎么拆、界限、验收怎么判）；让领导确认①塔尖是不是他要的②柱子齐不齐（归类分组不重不漏）③顺序对不对（逻辑递进按依赖排序）。**扫盲决策写进书**：3 步补盲清单的决策结果必须落进任务书——💡 采纳的拍板 →「我替领导拍的板」；💡 识别的风险/坑 →「界限」或「现状与任务 0」（让执行者带着坑干活，坑不只在访谈里说）；⚠️ 领导拍板的 → 对应节；📋 默认值 →「我替领导拍的板」标「猜的」。

**呈现形式**（触发：任务数 ≥3 或预估字符 ≥2000）——用 `scripts/pyramid-gen.py` 生成**金字塔图**（塔尖+塔身+护栏，颜色语义固定：红尖/橙柱/黄规则/绿护栏），让领导 5 秒看清结构；图后**附文字骨架**（每柱一行：任务名+一句核心动作）。短任务只用文字骨架不画图（避免过度设计）。图规格是「语言」不是「模板」——参数化生成（`--apex/--pillars/--base`），柱子 1-7 根自适应，AI 特殊情况仍可自由手画。**死规矩（预览格式）**：金字塔图**必须在对话里直接渲染给领导看**（SVG 图 + 文字骨架一并贴出），**不许建 HTML/文件存盘让领导自己打开**——预览是「领导亲眼看图点头」的交互，不是交付物；写进 `.goal/` 的文件只是 `pyramid-gen.py --out` 的中间产物，最终呈现必须在对话里。

**闸门 G5（写书前·人工）**：领导看图+文字骨架，确认①塔尖是不是他要的②柱子齐不齐③顺序对不对——全部点头才写正文。**图必须在对话里直接渲染（SVG），不许建 HTML 文件让领导自己打开**。脚本只提示不判（`stage-gate.sh 5` 输出核对清单）。

预览经领导点头才写正文；正文写成后跑 `scripts/coverage-check.sh` 核对覆盖清单，漏点=完整性失败，不许发出。

**6 交付。**最终回复只有三样，过程噪音（调研表格、中途更正、分析过程）一概不带：
- 一句用法：「在执行 agent 那边输 `/goal `，粘贴下面整段，发出去。」（`/goal` 是斜杠命令，没有单独输入框；没有目标模式的工具就直接粘贴发送。）附导读：领导只看三处——开头「这活为什么干」两行、「我替领导拍的板」、末尾「完成条件」的两条硬指标。交付任务书同时，附盲点提示（≤5 行）：「这版基于以下 N 个假设（标'猜的'的决策），其中 ⚠️ 标记的如果实际不同会影响方案方向——建议优先确认。」（假设清单从书里「我替领导拍的板」/「现状与任务 0」复述，不新增内容——坑已在书里，这里只是提示领导去确认）
- 任务书代码块，整块可复制。
- 一句收尾：「跑完回来说一声，我来验收，给你 5 行内的人话报告。」

**一个目标、一次粘贴。**不许第二条 `/goal`、不许让领导存文件、不许发明开工命令。

**7 验收，是管理者的活。**明卷（验收命令）在书里，目标模式自己盯；暗卷——2–3 条执行者看不见的抽查——自留在会话侧 scratchpad，不进书。领导回来喊一声，你亲自复跑明卷＋暗卷，给 ≤5 行人话报告：过没过／干成了什么／遗留问题／下一步。执行者不能自己批卷，领导全程零命令。摸不到执行环境时才退化为「验收官提示词」，让领导转贴给一个没参与执行的 agent。领导说「不对/不满意」时，不重做——用同一套澄清流程把反馈逼成三件套：哪里不对→差在哪→往哪改，再按修改后的目标重写书；**重写版是修订流程，不占 `/goal` 次数**。

## 写书规则

冲突听谁：可判定 vs 价值观=改写可判定；篇幅 vs 完整=删重复保核心红线；探索 vs 执行=都产任务书。
任务书六节的结构规格与验收改法见 [references/anatomy.md](references/anatomy.md)——它规定每节写什么，措辞和详略由你贴合任务判断。**内部术语不许进书**（如「暗卷」「探索型」），要表达时查 [references/glossary.md](references/glossary.md) 的人话版本。对话示例（好例/坏例）见 [references/examples.md](references/examples.md)。

**≤4000 字符，硬上限**（`/goal` 官方限制，超了粘不进去）。字符花在不查就会踩的坑上，不写执行者打开仓库一眼能看到的事实；砍调研过程、重复规矩、背景故事。

**完整性防线（防偷删）**：写书前先物化覆盖清单 `.goal/coverage.txt`——按 [references/anatomy.md](references/anatomy.md)「覆盖清单生成骨架」的**九维**（Why/Done/Proof/Anti/Bounds/Trade/Unknown/环境资源/风险卡点）逐维列出本任务书必须包含的每个信息点（一行一个，可带关键词）；**来源 = 五层面答案 + 调研事实（带来源）+ 补盲决策 + 提问拍板的机械汇总**，不是临场拍脑袋。全书写完、发出前跑 `scripts/coverage-check.sh .goal/coverage.txt <任务书>`，清单要点全部命中才算完，漏点=偷删嫌疑，不许发出。**超 4000 必须真拆**（不许压缩偷删、不许只写概念）——拆 N 本、每本目标、**接缝验收命令**（第二本开工前先跑哪条命令确认接缝完成），给领导点头后分次发出；写不下又不拆 = 失败。拆书方案要素与判定见 anatomy「完成条件」节。

**验收写什么看任务形态**：能写成命令的写命令（带防作弊），只能靠人判断的（文风、体验、结论质量）写抽查点+领导亲验。

**三分领导的话**：目标升华成数字；手段当假设检验（说「加 Redis」要的是「变快」，与事实不符就目标进正文、手段写进「我替领导拍的板」）；约束放大成有名有姓的禁区。

**富规格优先**：目标领域里已有的规格性文件——代码向的测试套件、schema、验收脚本、设计稿；业务向的需求文档、竞品分析、模板、品牌手册——直接写路径当规格，别用散文复述；「测试名本身就是业务要求」就是这一条。调研的一部分，就是找出哪个文件是规格。**死规矩（每任务必给从哪下手）**：任务描述不许只写目标——每个任务必须有「从哪下手」的具体路径（文件/命令/参照物/规格路径），否则执行者不知道第一步做什么（4000 字符挤掉细节=执行者理解不了，比超字数更糟）。

**法与情报分家**：「不许」是法，违反即不合格，每条溯源到一次实测或一次领导裁决；「建议」是情报，执行者有更好的路可以走、在 `PROGRESS.md` 记一句为什么。把情报写成法，是替执行者做它临场更懂的决定。

## 防五种死法（全流程护栏）

1. **作弊达标**（最重要）：说「让测试绿」，最省力的是加 `.skip`、放松断言、mock 被测对象、删测试、`|| true`——不是它坏，是目标函数写错。对策：基线不可退（测试数／覆盖率 ≥ 基线、skipped 0）、点名禁止具体姿势、判卷标准冻结、暗卷自留。判卷冻结与基线不可退用脚本强制：`guard.sh snapshot/verify`（判卷文件 sha256 冻结）、`guard.sh record/check`（数字基线 ≥ 对比）——写书时把这两组命令写进任务 0 和验收节；脚本在 `scripts/`，任务书里用绝对路径。若「测试要绿」与「实现不许改」冲突而代码真有 bug：点破并给方法（characterization test：锁当前行为＋标 KNOWN DEFECT），否则它必偷改实现。**非代码目标（产品/内容/流程）的作弊姿势**：凑数结论、编造数字、只贴「做完了」不贴证据、抄现成方案当原创——对策同款：点名禁止姿势、判卷标准冻结、暗卷自留、结论带来源可复现
2. **幻觉命令**：它会平静地编造命令再甩锅环境——书里每条命令你必须亲手跑过，摸不到就写进任务 0 让它查实
3. **失忆**：进度写 `PROGRESS.md`，接手会话先读它别重做；任务 0 过后先写 ≤10 行开工回执（理解的目标／顺序／最大风险）再动工；单任务一个会话内做得完
4. **一条道走到黑**：任务 0 兼前提核验，量出的数字对不上就停；同一验收连败 3 次换项；结果比基线差就回滚如实报告——「没做成但说清了」合格，「做了但更糟」不合格
5. **静默事故**：坏了不发信号的（假绿灯、失效报警器）配反向验证——亲手制造一次失败证明会响，贴输出。判据：问「这里坏了谁会知道」，答「没人」就要

## 多 agent 并行（领导点头才拆）

写书发现内容超 3500 字符时，先把拆书方案（拆成 N 本、每本目标、接缝在哪）给领导看，点头才拆——**拆书方案要素与判定见 anatomy「完成条件」节**，不重复列。**不许擅自拆，也不许为保 4000 硬压**。每份书带同一段「全局」（整体干什么、谁管哪段、接缝在哪——接缝没人接是头号事故）。地界错开，共享写入点（lockfile 等）指定唯一归属。A 的证据经过 B 的战场只列存疑不动，B 每次 rebase 后重跑取证。建设与删除不给同一个 agent。写明「合并排队变慢是新常态，不要自行协调、不要改 CI」。

## 发出前自检

发出前必跑 `scripts/stage-gate.sh 6 <任务书>`（**G6 写书后**）——它自动调 goal-lint + coverage-check + **回归目标**（任务书必须含「这活为什么干」塔尖），并输出「重点人工复核清单」（猜的决策/假设/拆书方案/硬指标）给领导过目。goal-lint 内部的机器检查项（字符数/六节齐全/黑名单词/产物路径合规/完成条件可执行判定）以 `goal-lint.sh` 实际输出为准，此处不重复罗列；拆书方案要素见 anatomy「完成条件」节，产物路径规则见 anatomy「工作产物放哪」节。

`--self` 模式（`goal-lint.sh --self SKILL.md`）体检 skill 本体，发布新版本前必跑。
