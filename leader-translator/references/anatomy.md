# 任务书 · 结构规格

六节，顺序固定：「我替领导拍的板」放最前（领导发出前扫一眼就能改判），「完成条件」放最后（两条硬指标收拢一切）。整本 ≤4000 字符，单任务的书通常 1500–2000。本规格不配样文——照规格自己写，措辞贴合当下的任务，别套任何现成句式。

- 版本：v2.5（对齐 SKILL.md v5.7.0）
- 创建日期：2026-08-01，更新：2026-08-03

## 覆盖清单（coverage.txt）生成骨架

写书前物化 `.goal/coverage.txt` 时，按**九维**逐维列出本任务书必须包含的信息点（一行一个，可带关键词）——这九维覆盖一本合格任务书所需的全部信息类别（归类分组，不重不漏）：

| 维度 | 含义 | 对应任务书节 |
|---|---|---|
| Why 目的 | 这活为什么干、干完世界什么样 | 开头「这活为什么干」+ 让步顺序 |
| Done 完成态 | 干成什么样算完成 | 「完成条件」两条硬指标 |
| Proof 验收证据 | 怎么证明干成了（可判定） | 任务 N 验收命令 + 反向验证 |
| Anti 反作弊 | 不许用什么姿势达标 | 「规矩」防作弊点名 |
| Bounds 边界 | 只许碰哪、不许碰哪 | 「界限」白名单/判卷冻结/顺手活 |
| Trade 取舍 | 没问出口的默认值、让步顺序 | 「我替领导拍的板」+ 开头让步顺序 |
| Unknown 未知 | 查不到的、假设未验证的、A 型加分项 | 「现状与任务 0」+「我替领导拍的板」猜的 +「以后可以加」小清单 |
| 环境资源 | 摸到的环境、基线数字、可用工具 | 「现状与任务 0」实测 |
| 风险卡点 | 收不回的操作、止损线 | 「界限」+「完成条件」止损 |

**来源**：覆盖清单 = 五层面答案 + 调研事实（带来源）+ 补盲决策 + 提问拍板 的机械汇总——不是 AI 临场拍脑袋列。漏点 = 偷删嫌疑（`scripts/coverage-check.sh` 拦截）。

## 开头（不带标题，五件事各一句）

- 你是执行者，这份文档是你唯一的任务来源；中途没人可问，拿不准的写进 `BLOCKED.md`（待裁决清单），跳过继续做别的，最后随交付提交
- 断了、换新会话：先读 `PROGRESS.md`（进度记录）接着做，别重做；每做完一项立刻更新
- 这活为什么干：一句意图，为什么干＋干完世界什么样——书里没写到的情况，执行者靠它自己裁
- 两个要求打架时的让步顺序（如「算得对 > 做得全 > 做得快」）
- 死规矩与参考的分界：「只允许」「不许」违反算失败；「建议」有更好的路就走，在 `PROGRESS.md` 记一句为什么

## 我替领导拍的板

没问出口的每个决定一行：问题 → 默认值（标「猜的」）｜猜错的代价。领导发出前可改；执行者按默认走，不停下来等。
写不出机器可判命令的目标（文风、体验类）也记在这里：改成抽查点＋领导亲验，注明这活只能半托。
领导在访谈/提问中被砍掉的需求，逐条写进本节末尾「以后可以加」小清单，不消失。

## 界限

- 白名单：只允许改哪些路径＋新建文件，其余只读——用白名单不用黑名单，黑名单永远列不全
- 判卷标准（测试、验收脚本、CI 配置）碰都不许碰；无 git 时给每个文件的 sha256 指纹（文件内容的数字摘要，交付时必须一字不差）——用 `scripts/guard.sh snapshot` 冻结、`guard.sh verify` 对比，任务书里写脚本绝对路径
- 点名最诱人的顺手活（那个一行就能修的 bug、顺手重构、顺手装工具），写明进 `BLOCKED.md` 待裁决；收不回的操作（删数据、改权限）停下写 `BLOCKED.md` 做别的

## 工作产物放哪（关键约束集中点）

**所有工作产物必须放执行者工作区下的 `.goal/` 子目录**，路径写法只两种：
- 相对路径：`.goal/PROGRESS.md`（跟执行者工作区走）
- 占位路径：`<工作区>/.goal/PROGRESS.md`（领导实际工作区占位）

**三条禁令**（`scripts/goal-lint.sh` 机器拦截，不必逐字复述）：
- **禁裸名**：`PROGRESS.md` 不带路径前缀 = 违规
- **禁预埋**：不许出现 `/Users/xxx` `/home/xxx` `C:\xxx` 等绝对路径——他人环境无此路径，预埋必坏
- **禁指 skill 本体**：不许指向 `skills/`、`技能配置` 等 skill 安装目录

**备份快照保留多久？**——可判定标准：连续 3 个验收轮验证全过 + 期间无回滚 + 距上次改动 ≥2 天，删前先问领导（删前必须问，不许自动删）。

**管理者流程中间产物**（不入任务书，管理者侧自留）：`.goal/gate-1.txt`～`.goal/gate-4.txt`（六道闸门 1-4 步的产出物校验输入，见 SKILL.md「六道闸门」段），同样走 `.goal/` 相对路径。

## 现状与任务 0

- 实测数字逐条带来源与日期，查不到的标「猜的，没验证」；能提前实证的关键结论（如「只改实现就能全绿」）写进来，提前拆掉借口
- 任务 0：跑指定命令核对上面的数字，不存在的命令、空转的假检查当场记 `BLOCKED.md`；对不上就停，证据写 `BLOCKED.md` 最上面，只做不受影响的部分；核对无误后把「理解的目标／顺序／最大风险」≤10 行写进 `PROGRESS.md` 再动工

## 任务 N

每个任务包含：一句话目标带数字；从哪下手一句（多任务按依赖排序，说清为什么它排前面）；死规矩写成「做 A，否则 B」并带具体后果；验收＝命令＋机器可判的判定（含防漏判定，如「跳过 0」）；反向验证＝故意制造一次失败、贴变红输出、还原后贴全绿——凡是「坏了没人会知道」的检查都要这一步。
**验收命令避免依赖行号**（如 `awk NR>=63&&NR<=71`）——改用段标记定位（如 `awk '/## 发出前自检/,0'`）；行号一变动验收就悄悄失准，属于静默事故。

## 内部分工

任务涉及主观判断、视觉质量或非代码验收时，任务书含本段（代码类有机器可判命令，不需要）。有子代理能力的工具：执行者完成后，由独立子代理当审卷官，逐条跑本节验收清单，如实汇报通过/失败，失败的不许自己修。
审卷官汇报格式：✅ 通过 N/M ｜ ❌ 哪条 + 实际 vs 期望 + 修复方向。没有子代理：不写本段，走“领导转贴验收官提示词”的老路。本节只放明卷；暗卷永远不进书，由管理者自留、验收时出示。

## 规矩

- 防作弊点名到具体姿势：跳过测试（skip/todo）、放宽判断、把被测对象换成假的（mock）、删测试、改阈值或验收脚本、`|| true`（失败也当成功）——全算失败；测试数／覆盖率只许 ≥ 基线（用 `scripts/guard.sh record/check` 机器对比，别靠口头保证）；补测试类任务加「实现目录 `git diff` 为空（业务代码一行没动）」
- 不新增流程、权限、依赖，必须加的写 `BLOCKED.md`
- 同一条验收连败 3 次换下一项；结果比开工差就回滚如实报告——「没做成但说清了」合格，「做了但更糟」不合格
- 项目自有纪律（分支／PR 规则、提交前检查）写在这里

## 完成条件（关键约束集中点）

- 两条硬指标：一条度量领导要的结果（不是工作量），一条守约束（指纹没变、回滚＝0 之类）
- 一句「每条都要在对话里贴实际命令输出（含反向验证的红→绿证据），只说做完了不算」——判完成的小模型不跑命令、不读文件，只认对话里贴出的内容
- `BLOCKED.md` 随交付提交，空的也写「无」
- **止损：跑满 5 轮即停**——如满轮仍未完成，如实汇报卡在哪、还差什么；不要无止境重试
- **超 3500 字符必须带「拆书方案」节**（`scripts/goal-lint.sh` 拦截）——拆成 N 本、每本目标、接缝在哪；超限又不拆 = 不许发出，禁止为保 4000 硬压缩偷删

## 探索型：改五处，其余同款

领导要的是答案本身（调研、选型、「该不该做 X」）时，硬指标只会换来凑数的答案：

1. 完成条件换成学习目标：结论条数设上限、每条附来源与日期或可复跑的复现步骤——宁收 2 条实的，不收 10 条凑的
2. 预算换成可承受损失：最多烧多少时间／查多少来源，烧完就交卷，交「目前最优＋还没排除什么」
3. 防作弊主防编造：凑数的结论、查无此文的引用、没跑过的「实测」都算作弊；每条结论要经得起领导随机抽一条、10 分钟内复现
4. 此路不通＝合格交付：带证据证明某方向是死路（死因＋原始输出），按完成计
5. 共同未知→最小实验：连 AI 也无法从现有信息推断的（假设、选型结论、效果预判），不写「你去调研」，写成实验设计四件套——假设 H：____（只改一个变量：____；成功信号：____；失败信号：____；跑完记录：____）。信号要能机器可判或领导可亲验，别写「感觉不错」这类不可判信号
