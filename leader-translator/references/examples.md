# 对话示例 · 对与错

两个对话示例，同一个需求——「想做一个团队周报汇总工具但说不清需求」。好例是标准走法（含六道闸门 G1-G6 演示）；坏例是常见翻车。看的时候对照 SKILL.md 流程（理清目标→调研→盲点扫描→提问→路径预览→写书→交付→验收）和 anatomy.md 六节骨架。

- 版本：v3.3（对齐 SKILL.md v5.4.0）
- 创建日期：2026-08-01，更新：2026-08-03

## 好例：先把需求问清楚，再写书（每步过闸门）

> 领导：我想搞一个团队周报汇总的东西，但我自己也说不清到底要什么样。

**管理者**：你只需描述你想做的事，剩下的我来问。

**理清目标（五层面定义，产品/工具类目标必走）**：
1. 给谁用？—— 推荐 A：团队几个人收周报的负责人；B：全体成员自己看
2. 解决什么？—— 推荐 A：把散在各处的周报收齐、汇总成一份好读的；B：提醒谁没交
3. 在哪用什么形态？—— 推荐 A：网页工具，链接打开就能填；B：企业内部表格/文档
4. 用起来什么画面？—— 推荐 A：每人填个表单，周五自动汇总成报告；B：领导点开就看到谁交了谁没交
5. 绝对不要什么？—— 推荐 A：不要做成复杂系统，够用就行；B：不要动现有的企业流程

> 领导：差不多就这样，给负责人用，收齐汇总成报告，网页就行，别整复杂了。

**闸门 G1（定义）**：五层面答案写 `output/gate-1.txt`（5 行，每行一层）→ `stage-gate.sh 1` → ✅ 过，进步骤 2。

**调研**：管理者用联网搜索查现成方案——搜「周报汇总工具/周报收集工具」结论：飞书/钉钉/腾讯文档有表格模板但无自动汇总成报告；开源项目无对口（来源：搜索 3 个结果页均不满足）。数据量级（几十人还是几百人）查不到，标注「假设，未验证」。

**闸门 G2（调研完）**：调研记录写 `output/gate-2.txt`（含搜索来源 URL +「假设，未验证」标注，🔍 项清零）→ `stage-gate.sh 2` → ✅ 过，进步骤 3。

**盲点扫描（AI 补盲，💡 为主轴——外部盲区优先，每条带来源+决策引导）**：
- 💡 联网查到：周报数据量级决定要不要分页/搜索——判断维度：预计条目数；<100 条不用分页、>500 条必须分页；拿不准就先不分页但留接口
- 💡 我的知识（B 推断级，⚠️ 未验证）：汇总报告给谁看决定输出格式——只给负责人看=网页即可；要发老板=需导出/正式格式；建议先按网页做，导出留后路
- ⚠️ 周报谁交、多久一次：需要你拍板
- 📋 数据从哪来：默认「每人自己填」（猜的）
- 📎 有没有现在用的周报模板：发我一份，照着做不跑偏

**闸门 G3（补盲）**：补盲清单写 `output/gate-3.txt`（含 💡×2 主轴项）→ `stage-gate.sh 3` → ✅ 过，进步骤 4。

**提问（≤5 个，每个带选项+推荐）**：
1. 周报数据怎么进来？
   - 推荐 A：每人填一个简单表单，你收汇总（最省事，先跑起来）
   - B：从你们已有的表格/文档里自动读
   - C：还没想好，你来建议
2. 汇总结果给谁看？
   - 推荐 A：负责人自己看，发群里给团队看
   - B：要发给老板，得能导出/转成正式格式
3. 这活要不要先找现成工具？—— 推荐 A：先花半小时搜现成的，真没有合适再自己写；B：就是要自己做一个
4. 一个"够用"的版本，你希望多久用上？
   - 推荐 A：这周就能用上，先糙后精
   - B：不着急，做扎实点
   - 或：给我本地文件/图片/URL / "帮我搜 X"

**管理者（每轮结束小结，逐轮确认）**：目前我听懂了的——你要一个把团队周报收上来、汇总好给你看的网页工具；不确定的是数据怎么进、给谁看、自己做还是用现成的。对吗？

> 领导：对，就这个意思。表单收就行，我自己看也发群里，先找现成的，没有再做。

**管理者**：好，我先搜索一圈现成工具，有合适的直接给你，没有就写任务书。……搜完了，没有完全对口的，写书。

**闸门 G4（分类）**：提问记录写 `output/gate-4.txt`（含「目前我听懂了的」小结 + KANO 分类声明 + ⚠️ 项全部清零——"周报谁交"默认每人自己填、"给谁看"已确认）→ `stage-gate.sh 4` → ✅ 过，进步骤 5。

**路径预览（金字塔骨架 + 图，领导点头才写正文）**：
- 塔尖：给负责人一个每周自动收周报、汇总成一份好读报告的网页工具
- 柱子 1：搭收集表单（4 字段）
- 柱子 2：汇总展示页（按人分组一眼看全）
- 柱子 3：验收（表单能提交、页面有数据、不删原有文件）
- 顺序：先表单后页面（数据先进来才能展示）

**闸门 G5（写书前·人工）**：任务数=3 ≥3 → 用 `scripts/pyramid-gen.py --apex "…" --pillars "搭收集表单,汇总展示页,验收" --base "写书规则,防五种死法"` 生成金字塔图，**在对话里直接渲染 SVG 给领导看（不建 HTML 文件）**，图+文字骨架一起贴：

> 领导：对，就这么干。

**管理者**（写书 → 闸门 G6 写书后，交付——任务书六节齐全，产物带 output/ 路径）：

```
你是执行者，这份文档是你唯一的任务来源；中途没人可问，拿不准的写进 BLOCKED.md，跳过继续做别的，最后随交付提交。断了/换新会话：先读 PROGRESS.md 接着做，别重做。这活为什么干：给团队一个每周自动收周报、汇总成一份好读报告的工具，让大家周五不再在群里刷屏接龙。让步顺序：收得全 > 看得懂 > 做得快。死规矩：每条任务都是死规矩，改完必须过验收命令。

【我替领导拍的板】周报提交用表单，链接发给每个人（猜的：用问卷类工具最省事）；汇总结果自己看+发群（领导确认过）；先搜现成工具没找到合适的，自己做（已搜证）；每周五 18:00 提醒没交的人（猜的）。猜错的代价：表单没人填→改自动从表格读。

【界限】白名单：只允许改 <工作区>/周报工具/ 下的文件；不许碰：别人的代码目录。最诱人的顺手活（写 BLOCKED.md 待裁决）：顺手加个数据看板。收不回的操作：无（任务 0 先备份）。

【工作产物放哪】PROGRESS.md / BLOCKED.md 放 <工作区>/output/ 下（写 output/PROGRESS.md，禁裸文件名）；备份快照 <工作区>/周报工具.bak-20260801 保留到验收全过+无回滚再删（删前问领导）。

【现状与任务 0】实测（grep，2026-08-01）：<工作区>/周报工具/ 目录空，无现成代码；表单工具可用。任务 0：①备份：cp -r 周报工具 周报工具.bak-20260801 ②核对：ls 周报工具/ 为空、表单链接能打开，对不上就停，证据写 BLOCKED.md 最上面 ③核对无误后把「理解的目标／顺序／最大风险」≤10 行写进 <工作区>/output/PROGRESS.md 再动工。

【任务 1】搭周报收集表单：建一张表单（姓名/本周干了什么/下周计划/卡住的事 4 个字段），链接可发给团队。验收：curl 打开表单链接返回 200；填一条测试数据，后台能看到。

【任务 2】周报汇总页：把表单数据列成一张表，按人分组，一眼能看全。验收：curl 页面返回 200；页面包含测试数据的姓名与内容。

【完成条件】两条硬指标：1. 任务 1/2 验收命令全跑通，逐条贴实际输出；2. diff 周报工具.bak-20260801 周报工具 → 改动只落在新增文件，无删改。每条验收都要在对话里贴实际命令输出，只说做完了不算。BLOCKED.md 随交付提交（放 <工作区>/output/BLOCKED.md），空的也写「无」。止损：或已跑满 5 轮——满轮即停，如实汇报卡在哪、还差什么。
```

**闸门 G6（写书后）**：`stage-gate.sh 6 任务书.md` → goal-lint ✅（六节齐/无黑名单词/output 路径合规）＋回归目标 ✅（书里有「这活为什么干」塔尖）＋重点人工复核清单（"猜的：问卷类工具最省事"等 2 项）给领导过目 → 领导确认 → 交付。

**管理者**（收尾）：跑完回来说一声，我来验收，给你 5 行内的人话报告。

**为什么：** 开场白一句话定住节奏（触发必说固定句）；产品/工具类目标先走五层面定义（把「说不清」逼成五问，领导好答；领导说得清的层只确认不啰嗦）；调研必须真用工具带来源（联网搜/知识库/实测，不许拿已知硬推）；盲点扫描以 💡 补盲为主轴、**外部盲区优先（我的知识/联网查到/知识库，带来源）**、每条 💡 带决策引导（领导没想过，要给路）、≤8 行（领导先看到"我没想过但需要想"的事）；提问 ≤5 个、**只问领导唯一知道的事**（内部常识）、每个带选项+推荐、末尾带兜底；每轮结束「目前我听懂了的」复述确认；**六道闸门 G1-G4 每步物化产出物过脚本（防跳步）**；写书前给金字塔路径预览（任务 ≥3 用 pyramid-gen 画图，**在对话里渲染 SVG 不建文件**）+ **G5 领导人工点头**；任务书六节齐全、产物带 `output/` 路径、验收全是可跑命令、无内部术语、猜的决策全写进「我替领导拍的板」（让领导能改判）；**发出前过 G6（脚本+重点人工复核）**。

## 坏例：不澄清就猜，书里全是坑（闸门全被跳过）

> 领导：我想搞一个团队周报汇总的东西，但我自己也说不清到底要什么样。

**管理者**：行，明白了。你是要做个周报工具，我来安排。先确认几个问题——你们团队几个人？周报是每个人自己写的对吧？汇总是不是要自动？要不要做成网页？数据库用什么？接口用什么？前端用什么框架？部署到哪？用不用考虑响应式？登录和账号体系要不要？每人填完要能改吗？……

**管理者**（没等回答，继续）：我猜你们大概 10 个人，周报写在一个共享表格里，我做个页面自动汇总。验收我就看看页面长啥样，应该没问题。对了，这里有个内部概念叫「暗卷」，我自留验收用，你不需要知道。我给你写个简单方案，你看看吧。

> 领导：？？？我还没说清楚呢。而且你问的我都答不上来。

**管理者**：没事，我按我理解的来，先这样吧。（交付——任务书骨架：）

```
你是执行者，这份文档是你唯一的任务来源。这活为什么干：做团队周报汇总工具。任务 1：做个周报页面；任务 2：汇总数据。完成条件：页面能打开、数据能汇总。
```

**坏在哪（对照六道闸门）**：
- **闸门 G1（定义）被跳过**——五层面没走完就猜（团队人数、数据来源、给谁看全拍脑袋），`gate-1.txt` 没物化，`stage-gate.sh 1` 根本跑不了
- **闸门 G2（调研完）被跳过**——没联网查现成工具、没查知识库，全凭猜（"我猜你们大概 10 个人"），无任何来源，`gate-2.txt` 缺失（新规则：无来源的调研记录=没调研）
- **闸门 G3（补盲）被跳过**——没有 💡 外部补盲清单（领导看不到"你没问但需要他定"的事；且 💡 必须带外部来源+决策引导，不是内部常识凑数）
- **闸门 G4（分类）被跳过**——提问一次抛 10 个以上、无选项无推荐，且没有「目前我听懂了的」小结、KANO 分类声明、⚠️ 项（给谁看/数据来源）没清零就冲进写书——`stage-gate.sh 4` 会当场卡住
- **闸门 G5（写书前·人工）被跳过**——没有路径预览，领导不知道你要怎么达成
- **闸门 G6（写书后）被跳过**——任务书无验收命令、无界限、无「我替领导拍的板」、产物无 output/ 路径（goal-lint 六节检查当场 fail）

**其他错误**：把「暗卷」这种内部术语甩给领导（内部概念不许出现在书里，要表达就查 glossary 的人话版）；不给兜底（末尾没有"或：给我文件/URL / 帮我搜 X"）。**教训：六道闸门不是流程装饰，是卡住"不问就猜"的唯一防线——每一步的 gate-N.txt 没物化，就是没做完这一步。**
